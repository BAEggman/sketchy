# 독립안 5 — 목차·그림·문답·재생을 하나의 학습 단위로 맞추는 재설계

작성일: 2026-11-20. 이 문서는 Opus가 실행할 계획이며, 사이트 수정·그림 생성·배포를 하지 않았다. 다른 독립안은 열람하지 않았다.

## 1. 판단의 출발점과 확인 범위

현재 문제는 그림의 미감만이 아니다. 한 단원을 선택했을 때 어떤 선수 지식을 알고 있어야 하는지, 같은 인물이 어느 책에 무엇을 했는지, 본화·단서 확대·음성·정답이 같은 사실을 말하는지, 자동 재생이 어디까지 진행하는지가 함께 어긋난다. 따라서 **교과서의 사실 → 학습 단위 → 장면과 단서 → 문답 → 목차와 재생**을 동일한 ID로 연결하는 것이 이 안의 중심이다.

직접 확인한 자료:

- 사용자가 제공한 감사 기록과 최신 요구 전체.
- 로컬 복원본 `work/sketchy-v7-resume/src/lessons/lesson_map.json`과 일부 `l/*.json`의 구조·문장. 이 복원본은 최신 Antigravity 결과라고 확인되지 않았다. 그림을 전수 시각 검사한 것이 아니다.
- 위 복원본의 과별 JSON은 66개지만, `lesson_map.json`의 `lessons` 항목은 191개였다. 서로 다른 분모를 합쳐 “전수 완료”라고 하면 안 된다.
- `hist-07` 제목은 `349→354→359→360→361`이지만, 정거장 13에는 `349→354→359→359→360→361`이 있고, 資生經과 鍼灸大成이 각각 359로 연결되어 있다. 제목의 증가 수열만 외우는 설계는 이 중복 관계를 잃는다. 이 값들은 복원본의 기록을 확인한 것으로, 역사적 수혈수의 출전 검증 완료를 뜻하지 않는다.
- 공식 Sketchy의 Symbol Explorer/Review Card 설명, MDN의 재생·저장 동작, 인출 연습 원 연구를 확인했다. 하단에 URL을 남긴다.

이후 공통 근거 묶음 `/tmp/sketchy-opus-plan/evidence/common.md`와 `current-observations.md`를 전달받아 최신 기준을 갱신했다. 최신 공개 `main`은 2026-11-18의 `539bab2a87625459874739246d0c5d8ca931d257`, `v7.0-carbon`, 227과다. 루트가 6장 실물을 확인한 관찰 기록을 공유했으며, 나는 그 관찰 결과와 아래 최신 코드를 읽었다. **내가 최신 227과 그림을 전수 시각 확인했다는 뜻은 아니다.**

최신 근거로 계획에 반영한 수정:

- `hist-03b`: 검은 구슬이 든 열린 상자와 바닥의 열쇠가 이미 있다. “아예 없다”가 아니라 **왕빙이 열쇠로 여는 행위·귀속이 약하다**가 현재 문제다.
- `hist-02a`: 양·도공·홍학/안경·붉고 검은 자료를 합치는 큰 독·집주전자가 이미 있다. 합편 아이디어는 보존하고 입력 문헌의 식별, 결과 저서 전체, 기여/의의를 보강한다.
- `hist-06b`: 오이씨→敖氏, 금거울·혀 등의 소품은 보존 후보다. 증보의 전후 관계는 소품 수가 아니라 실제 행위로 표현해야 한다. 12→24 추가→36의 정확한 문헌 관계는 원문 확인 후 채택한다.
- `hist-07a`: 최신 제목은 `349→354→359→359→361`이며 360이 빠져 있다. 醫宗金鑑 361을 교재 기준 확정이라고 적었지만, doc4 자체에 醫宗金鑑·鍼灸逢源/361이 묶인 출처 충돌이 보고됐다. 李學川/鍼灸逢源 노드도 없다는 관찰이다. 따라서 숫자 암기 재설계보다 **책·수치 귀속 검증과 누락 노드 복원**이 선행한다.
- `new-gr-14`: 띠·그물·죽마는 있으나 공간 유주가 약하다. 陽蹻의 끝점이 현재 JSON의 風府와 DOCX의 風池로 다르므로 한쪽을 임의로 정답화하지 않는다.
- 원본 manifest 59개가 실제 존재하며, 추가로 총강 통합 DOCX 제3~11장 텍스트 5,444문단이 발견됐다. 기본서 12장 체계와 총강의 장 체계가 달라 양쪽 목차 crosswalk가 필요하다. OCR성 텍스트는 원문 대조 대상이다.
- `CARBON_REPORT`의 평균 97.04%는 자체 AI 판독 결과이며, 회상 성공률이나 사람 전수 검수 증거로 사용하지 않는다.

아직 직접 확인하지 못한 것: 최신 자산 전체의 실제 그림, 사용자가 쓴 DOCX 전체 문단과 실제 목차의 완전 대조, Suno 醋法 곡의 가사, 각 의학사·경맥 사실의 최종 출전. 아래의 구체 cue는 **설계 후보**이며, 이 단계에서 학습 효과나 실제 그림 구현 성공을 입증한 것이 아니다.

## 2. 먼저 고정할 다섯 가지 결정

1. **목차의 기준은 사용자의 기본서 원문이다.** 그림 파일명·생성 시점·현재 카드 번호를 교과서 순서로 오인하지 않는다. 한의학기본서와 한의학총강의 순서가 다르면 기준 교재를 명시하고, 다른 책의 대응 절을 연결한다. 공통 조사에서 제13~16장 폴더가 비어 있고 별도 한의학개론 PDF가 발견됐으므로, 폴더 내용만으로 교과서가 제12장에서 끝난다고 고정하지 않는다. PDF 목차·본문을 읽어 해당 범위를 확정한다.
2. **그림 한 장과 시험 사실 한 개는 같은 크기가 아니다.** 한 장에 5개 사실이 있으면 5개가 각각 관찰·질문·역회상 가능한지 검사한다. 인물만 그렸는데 저서까지 커버했다고 세지 않는다.
3. **좋은 음운 단서는 보존하고 관계를 보강한다.** 全元起의 전원 기립, 扁鵲의 납작 까치, 薛己의 백설기처럼 짧고 일관된 연결을 기준으로 삼는다. 뜻풀이가 독음 연결보다 우선하지 않는다.
4. **그림에 넣지 못한 사실을 숨기지 않는다.** 정확한 원문·전체 혈명표·긴 목록은 문답과 표 복원으로 담당할 수 있다. 그림만 보고 복원 가능한 사실과 설명을 읽어야 아는 사실을 별도로 보고한다.
5. **자동 재생 완료는 암기 완료가 아니다.** 보기·듣기의 편의는 제공하되, 학습 성공은 가린 상태에서 사실·한자·관계를 회상한 결과로 판단한다.

## 3. 교과서 목차와 그림 위계를 만드는 데이터 계약

Opus는 먼저 기준 자료와 최신 자산을 동결하고, 다음 장부를 만든다.

| 장부 | 필수 내용 | 막으려는 실패 |
|---|---|---|
| 원문 사실 장부 | `factId`, 교재·판본, 장/절, 문단·표·쪽, 한자 원문, 시험형 질문 | 문답을 줄이면서 사실이 사라짐 |
| 학습 단위 장부 | 불변 `lessonId`, 주 목차 절, 정렬 키, 선수 `lessonId`, 다루는 `factId` | 중복·누락·뒤섞인 학습 순서 |
| 자산 장부 | 본화·단서·썸네일·음성·대본 경로, 내용 revision, 해시, 제작 출처 | 본화는 새 판인데 단서·음성은 구판 |
| 단서 사전 | `cueId`, 그림 대상, 발음, 표적 한자, 역할, 이미 쓰인 다른 의미 | 대머리가 腎이었다가 脾로 바뀜 |
| 판정 장부 | 사실 정확성, 그림 실재성, 회상 적합성, 보존/수정/교체/보류, 이유 | 설명만 맞고 그림은 틀린 결과를 통과 |

학습 단위의 ID는 파일명이나 목차 번호와 분리한다. 그림을 재생성하거나 목차가 이동해도 같은 사실 묶음의 ID는 유지한다. 단원을 분할·통합할 때만 명시적인 ID 이행표를 만든다.

교과서 목차가 일차 탐색 경로다. 각 절 밑에 실제 그림 링크를 순서대로 둔다. 어떤 그림이 두 절에 필요하면 동일 그림에 대한 교차 링크를 만들고, 자산을 복제하지 않는다. 같은 그림이 두 번 재생되도록 무작정 목록에 중복 삽입하지 않는다. 교재별 기준 목록과 재생 목록에서의 중복 제거 규칙을 문서화한다.

선수 관계는 목차 순서와 다르게 저장한다. 예를 들어 사암표는 五行의 生克 → 陰陽經의 五輸穴 대응 → 규칙 → 경별 정확 혈명 → 전체 표 인출이 필요하다. 유주는 체표 방향·기본 경맥 → 奇經의 경로 → 교회 관계 순으로 연결한다. 이 순서는 실제 DOCX 구조를 읽은 후 맞춘다. UI에는 필요한 항목만 “먼저 보기” 링크로 드러내고, 학습을 강제 잠금하지 않는다. 누락 ID·순환 선수관계·도달할 수 없는 그림을 검사한다.

기존 66개 파일·191개 manifest 항목은 과거판 인벤토리이며 최신 227과와 섞지 않는다. 최신본에서도 본화 수, 단서 수, 문답 수, 원문 사실 수를 따로 확정한다. 직접 읽은 현재 `build_player.py` 125행에는 ID 사전순 정렬이 있다. 이를 실제 교재의 명시적 목차 정렬 키로 바꾸고, 선수 관계는 별도 유지하는 것이 구체 수정 지점이다.

## 4. 전체 그림·대본을 어떻게 평가하고 보존할 것인가

각 사실에 다음 네 검사를 별도로 적용한다.

1. **의학 사실:** 원문·기준 교재와 일치하는가. 판본 차이와 수치 차이를 출전과 함께 남기는가.
2. **보이는 것:** 대본이 말한 소품과 동작이 실제 최종 픽셀에 있는가. 열쇠가 구슬을 여는가, 단지 손 옆에 있는가. 腑證이 변인지 음식인지, 喜按이 복부 압박인지 악수인지 실제 그림으로 판정한다.
3. **회상 연결:** 소품 → 독음/개념 → 해당 인물/저서/기여의 연결이 짧고 분명한가. 다른 정거장에 속한 사탕·땀·딸기를 끼워 넣어 경쟁 단서를 만들지 않았는가.
4. **판 사이 일치:** 본화·확대 단서·썸네일·음성·질문·정답이 같은 최종 revision인가. 독립 삽화를 본화 위 액자로 덧붙여 원래 대비를 가리지 않았는가.

보존은 이미지 전체만을 단위로 하지 않는다. 인물 외형, 특정 소품, 특정 문장, 발음 연결, 장면 관계를 따로 채택할 수 있다. 예를 들어 王冰의 얼음 인물은 좋지만 啓玄子 소품이 없다면 인물은 유지하고 손동작과 검은 구슬을 재구성한다. 탈락본은 이유와 함께 비교용으로 보관하되 최종 재생 목록에는 들어가지 않게 한다.

화풍 통일은 사실 회상보다 뒤에 둔다. 납작한 도식 자체가 항상 나쁜 것은 아니다. 위치·경로·표의 정확성이 필요한 부분은 정확한 도식이 낫다. 다만 본화의 사람·행동과 단서 도식의 대응 지점은 연결해야 한다. 유주 해부도와 정확한 표를 생성형 그림에 맡기지 않는다.

대본은 “보이는 대상 → 어떻게 읽는지 → 누구에게 속한 무슨 사실인지 → 시험에서 바꿔 묻는 대비” 순서로 쓴다. 설명을 늘려 실패한 그림을 변호하지 않는다. 최초 학습에서는 단서를 가르쳐야 하지만, 재노출 때마다 긴 해설을 들어야 복원되는 단서는 재설계한다. 한자 원문은 UI·정답에서 보존하고, 그림 내부 글자는 없으면 정확성이 무너지는 경우에만 예외 목록을 남긴다.

## 5. 구체 cue 후보: 채점 전의 제안

아래는 확정 그림 지시가 아니다. 각 후보가 담당하는 사실과 담당하지 못하는 사실을 명시한다. 기존 성공 cue는 사용자 판단을 존중하여 유지한다. `출전 확인 후`는 그 사실의 채택을 아직 승인하지 않았다는 뜻이다.

| 후보 | 눈에 보여야 하는 물건·동작과 연결 | 복원할 범위·역회상 질문 | 혼동 위험과 통과 조건 |
|---|---|---|---|
| 1. 全元起 + 素問 주석 | 기존처럼 한 공간의 사람들이 전원 일어난다. 일어난 이들이 서로 소문을 전하고, 인물이 받은 두루마리 여백에 설명을 붙인다. “전원 기립 → 전원기”, “소문 → 素問”, 여백 덧붙임 → 주석 | 인물·책·주석 행위. “누가, 무슨 책에, 어떤 일을 했나?” 최초 여부·시대는 별도 출전 확인 | 단순 대화가 ‘소문’으로 읽히는지 검증. 원문 편찬과 주석을 혼동하면 탈락. 인물만 떠오르면 부분 통과 |
| 2. 王冰의 啓玄子 | 기존 얼음 인물의 손이 **힌지와 열쇠 구멍이 있는 검은 구슬**을 열쇠로 실제 연다. 열린 두 반쪽과 열쇠 회전이 보인다. 開啓의 동작 + 검은 玄 + 구슬/작은 물체의 子를 한 행동으로 묶음 | 인물의 별칭. “얼음 인물이 검은 무엇을 어떻게 여는가, 이것은 그의 저서인가 호인가?” | ‘키=계’ 같은 약한 발음만으로 정당화하지 않는다. 子를 구슬로 표현하는 것은 자연스럽지 않을 수 있으므로 **啓玄** 회상과 **啓玄子 전체** 회상을 따로 측정. 반드시 별칭임을 학습 문답에서 고정 |

숫자 사전은 후보 7~10이 공유하며, 최신판의 익숙한 부호를 먼저 보존한다. 책마다 새 숫자 암호를 만들지 않는다. 핵심 변화는 새 암호 발명이 아니라 **해당 저서 가까이에서 세 자리·순서·귀속을 행동으로 묶는 것**이다. 평가 시 “사전 학습에 걸리는 노력까지 포함해, 현재 동굴 번지나 먼 배경 조합보다 유리한가”를 비교한다. 숫자를 그림 안에 쓰지 않았다는 이유만으로 더 좋은 mnemonic이라고 채점하지 않는다.

위 표에서 3~5의 일부 저서 제목이 아직 약하다는 점은 중요하다. 그림이 아름답고 대본이 유창해도 **정확한 책 제목·기여·의의 회상이 실패하면 미완료**다. 최종 심사자가 이 공백을 인출 카드로 분담할지, 더 나은 음운 후보를 재요청할지 결정해야 한다.

## 6. 단원별 학습 설계

### 의학사: 인물 중심 목록에서 사실 관계의 복원으로

각 인물에 `시대/활동국`, `이름`, `자·호·별칭`, `저서`, `편찬·주석·교정·증보·전승 등의 기여`, `최초·현존·집대성 등의 의의` 필드를 둔다. 생몰국과 활동국이 다르면 분리한다. 자·호·별칭은 실제로 확인된 것만 채운다. 빈 필드를 상상으로 메우지 않는다.

한 장면의 물리적 배치를 일관되게 한다. 시대/국가는 무대, 인물은 행위 주체, 저서는 다루는 물건, 기여는 동작, 의의는 전후 대비다. “최초” 금메달을 모든 종류의 최초에 같은 의미로 붙이지 않는다. 최초 전문서·현존 최초·최초 관찬 등 범위를 문답에 보존하고, 그림으로 구별되지 않으면 사실 커버리지에서 문답 전용으로 분류한다.

질문은 `인물→책`, `책→인물`, `기여→인물/책`, `호→인물`, `동시대 구별`, `틀린 교차 짝 찾기`를 모두 만든다. 陶弘景은 두 입력 문헌과 합본 결과를 3개 노드로 외우는 데서 끝나지 않고 누가 합쳤는지까지 답하게 한다. 왕빙의 호가 저서명으로 회상되는지도 검사한다.

### 奇經·경락: 정확한 경로가 중심, cue는 경로를 꺼내는 손잡이

DOCX의 기존 유주 mnemonic을 최우선으로 추출한다. 각 경맥을 `기시→주요 경유→종지/연결`, 체표 안팎·전후, 교회 관계, 관련 문답으로 구조화한다. 정밀 유주선은 코드/벡터/원본 해부도 기반으로 만들고 생성형 이미지의 인체 변형에 맡기지 않는다.

학습 순서는 전체 노선 보기 → cue로 노선 설명 → 경유점 일부 가리기 → 빈 신체 도해에 경로 복원 → 유사 경맥 교차 질문이다. 뜻풀이 허리띠·그물·죽마는 명칭 힌트일 뿐 유주 커버리지로 세지 않는다. 경락 전 범위의 五輸穴·原絡·郄·八會 등은 실제 교재 항목을 장부로 대조하고 임의로 “다 있을 것”이라 판단하지 않는다.

### 사암침법: 규칙 압축 + 정확한 혈명 인출

사암은 그림을 경마다 계속 늘리기보다, 오행·오수혈 표를 공유하는 소수 도식과 **정확한 표 복원**을 주 학습 도구로 삼는다. 원문에서 다루는 모든 표의 종류와 행/열을 먼저 확정한다. 正格·勝格·寒格·熱格 및 교재의 사암허실 분류를 동일한 용어인 듯 합치지 않는다.

1. 陰經·陽經의 五輸穴 오행 배속과 각 경의 실제 혈명을 별도 빈칸표로 인출한다.
2. 해당 교재의 보사 규칙을 읽고, 예시 한 행에서 왜 그 네 혈이 놓이는지 설명한다.
3. 행별로 `補의 두 혈 / 瀉의 두 혈`을 정확한 순서·한자로 회상한다. 순서를 무관하게 채점할지 교재 배열을 요구할지 문제 정의에 명시한다.
4. 단서가 풍부한 완성표 → 한 열 비움 → 한 행 비움 → 전체 공란 → 경·격을 섞은 질문으로 지원을 줄인다.
5. 틀린 혈명과 소속경만 집중 비교하고, 맞힌 행도 일정 간격 뒤 다시 전체 복원한다.
6. 공식으로 계산되는 것과 교재의 예외/다른 전승을 구분한다. 규칙으로 생성한 표를 정답으로 삼기 전에 원문 표와 모든 셀을 대조한다.

별도 그림은 자주 충돌하는 혈명과 예외에 한정한다. 사용자가 지적한 `解谿(胃)`와 `陽谿(大腸)` 오류를 필수 회귀 사례로 둔다. 단순 이름 맞추기 외에 **혈명→소속경→오행 성격→해당 표에서 補/瀉 자리**까지 연결한다. 임상 처방을 추천하는 기능은 추가하지 않는다.

인출 연습 원 연구에서는 지연 검사에서 반복 인출의 이점이 관찰되었다. 이를 본 프로젝트의 학습 설계 근거로 삼되, 사암표 전부를 특정 횟수·며칠에 반드시 외운다고 보장하지 않는다. 초기 운영 간격은 예를 들어 학습 직후·다음 날·3일·7일로 두고 실제 오류에 따라 조정할 수 있으나, 이 숫자를 연구가 확정한 최적 일정이라고 제시하지 않는다.

### 本草·炮製: 목록과 성질을 서로 다른 도구로

포제법별 대상 약물 목록은 교재 표를 그대로 기준으로 삼고, 사용자 곡의 정확한 가사/두문자와 대조한다. 한 음절이 어느 약명의 어느 부분인지 1:1 표를 만든다. 긴 목록을 짧은 절/박자로 묶되 모든 항목을 세어 누락을 검사한다.

각 약물에는 `정확 약명·한자`, `포제법`, `목적/변화`, `해당되는 교재 조건`을 분리한다. 목록은 노래·두문자·칸 채우기, 성질 변화는 전후 장면, 감별은 짝 비교가 맡는다. 醋·酒·鹽·薑 등 보조재의 그릇이나 색만으로 목록의 개별 약물을 대표하지 않는다. 개별 本草에서 성미·귀경·효능·주치·주의를 모두 그림 한 장에 과포화시키지 말고, 실제 교재의 중요도를 따라 일부를 시각화하고 나머지는 정확한 인출로 연결한다.

## 7. HTML 허브: 요청한 네 기능의 구체 동작

기능은 기존 그림 플레이어를 유지하면서 다음 네 가지를 더하는 범위로 묶는다. 별도 계정·공유 커뮤니티·점수 경쟁·자동 임상추천 등은 추가하지 않는다.

**현재 코드에 이미 있는 기능도 보존한다.** 직접 읽은 최신 `player.js`에는 시험 결과의 localStorage 저장과 JSON 내보내기, 음성 속도·음성 켜짐 설정, 과 내부의 정거장 자동 이동이 있다. 이것을 모두 새로 만들었다고 보고하지 않는다. 현재의 `S.auto`는 한 과 안 정거장 이동이므로 사용자가 원하는 **다음 그림/다음 과 자동 넘김**과 별도로 정의해야 한다. 본화 학습이 끝나는 시점은 해당 과의 마지막 필수 정거장 종료로 정하고, 그때만 다음 과 목록 제어기에 완료 이벤트를 전달한다. 두 계층이 각각 다음으로 이동하여 이중 전환하지 않게 한다.

현재 음성은 HTML 오디오 파일이 아니라 `speechSynthesis` 중심이다. `tts.speak`는 실패에 `done(false)`를 반환하지만 `playStation`의 콜백은 성공값을 무시하고 `heard` 표시와 `afterStation()`을 실행한다. 안전 타이머도 `stopAll()` 뒤 `afterStation()`을 실행한다. 따라서 **실패·시간 초과를 정상 청취 완료로 계산하는 현행 동작**을 바로잡는 것이 신규 자동 넘김보다 선행한다. 성공/오류/사용자 취소/시간 초과를 구분하고, 대기·재시도·수동 다음을 제공한다.

### 목차 행과 썸네일

각 그림 행은 `왼쪽 썸네일 / 제목과 필요한 선수 링크 / 오른쪽 별표` 순서다. 썸네일은 실제 최종 본화 전체의 축소본이며, 얼굴 일부만 잘라 장면을 알아볼 수 없게 만들지 않는다. 확대 보기와 그림 열기의 동작을 구별할 경우 표기를 명확히 한다.

썸네일에는 해당 장면의 의미 있는 대체 텍스트를 둔다. 별표 버튼은 그림 링크와 별도이며 누르면 페이지가 이동하지 않는다. 키보드 초점과 눌린 상태를 제공한다. 모바일에서는 제목 줄바꿈을 허용하고 별표가 화면 밖으로 밀리지 않게 한다. 이미지가 깨지면 숨기지 말고 제목·대체 텍스트와 다시 열 수 있는 경로를 보여준다. 하단 썸네일은 지연 로딩하되 현재 그림과 다음 그림은 미리 준비해 불필요한 백지 전환을 줄인다.

### 별표: 저장·복구·이행

별표는 `lessonId`를 키로 저장한다. 순서 인덱스·제목·파일명으로 저장하지 않는다. 그림을 바꾸거나 목차를 재정렬해도 별표는 유지된다. 데이터에는 앱 이름과 스키마 버전을 둔다. 클릭 시 즉시 UI를 갱신하되 저장 실패를 감지하면 “이 기기에서 저장되지 않음”을 작게 알리고 내보내기를 제공한다.

최소 JSON 내보내기/가져오기를 둔다. import 시 알려지지 않은 ID를 버리지 말고 보고하고, 중복·충돌은 기존 표시에 합치는 것을 기본으로 하되 전체 대체는 명시적 동작으로 분리한다. 단원 분할/통합 이행표는 사용자의 별표를 조용히 잃지 않게 한다. 분할 시 기존 별표를 각 자식에 계승했다는 안내를 한 번 남기고 개별 해제를 허용한다.

브라우저 `localStorage`는 origin별 저장이며, `file://`에서는 동작이 일관되게 보장되지 않는다. 따라서 정식 HTTPS 배포를 기준으로 검증하고 다운로드 HTML의 별표 영속성을 무조건 보장하지 않는다. 저장 차단·사생활 보호 모드에서도 그림 열기는 정상 작동해야 한다. 이 한계 때문에 작은 설정 export가 필요하다.

### 자동 넘김·반복의 의미를 고정

“다음 그림 자동 넘김”은 음성이 있으면 음성 종료 후, 없으면 사용자가 설정한 보기 시간이 끝난 후 다음 그림으로 이동하는 기능으로 정의한다. 음성이 없다는 이유로 즉시 넘기지 않는다. 기본 보기 시간은 사용성 시범에서 정하되 학습 효과의 최적값이라고 주장하지 않는다.

“전체 반복”의 전체는 **화면에 표시된 현재 교재/단원의 재생 목록**이다. 검색 결과나 별표 여부로 몰래 바뀌지 않는다. 플레이어에 목록 이름과 `현재/전체`를 보여준다. “구간 반복”은 그림 A부터 그림 B까지 양 끝을 포함하는 반복으로 우선 해석한다. 음성의 초 단위 A–B 반복은 별도 요청 없이는 넣지 않는다.

자동 넘김을 끄면 현재 그림 이후 진행이 멈추고, 반복 옵션은 기억하되 비활성 상태임을 보인다. 자동 넘김과 반복이 서로 다르게 몰래 진행하지 않게 한다. 페이지를 다시 열었을 때 설정·위치는 복원해도 **소리 재생을 강제 시작하지 않는다**.

## 8. 재생 상태와 예외 표

상태는 최소한 `준비`, `재생 중`, `일시정지`, `완료`, `오류`로 나누고, 하나의 중앙 제어기가 현재 목록·현재 그림·반복 범위·자동 넘김·활성 실행 토큰을 관리한다. 오디오와 타이머를 각 버튼이 독립적으로 다루게 하지 않는다.

| 상황/이벤트 | 해야 할 일 | 다음 상태·검증 |
|---|---|---|
| 처음 열기/새로고침 | 마지막 위치·설정 복원, 이미지 표시, 소리·타이머는 사용자 시작을 기다림 | 준비. 브라우저 autoplay 허용을 가정하지 않음 |
| 현재 방식인 TTS 시작/정상 종료 | 발화의 `start`와 `end`를 구분하고 활성 토큰의 마지막 문장 정상 완료만 정거장 완료로 인정 | 사용자 취소·`error`·watchdog 시간 초과는 완료가 아님 |
| 음성 있는 그림의 재생 시작 | `play()` 성공을 확인하고 재생 표시. 실패하면 대기/오류 안내 | Promise 성공 전 “재생 중”으로 확정하지 않음 |
| 음성 정상 종료, 자동 넘김 꺼짐 | 현재 그림에서 정지 | 완료. 반복 설정도 이때 이동시키지 않음 |
| 음성 정상 종료, 자동 넘김 켜짐 | 활성 그림의 종료 이벤트인지 확인 후 목록 계산 | 다음 그림 또는 아래 반복 규칙 |
| 음성 없는 그림 | 이미지 표시·디코딩 확인 후 보기 시간 측정 | 사용자가 재생을 시작한 경우에만 타이머 가동 |
| 음성 404/디코딩 실패/재생 차단 | 현재 그림 유지, 재시도·수동 다음 제공 | 오류/일시정지. 순식간에 다음을 연쇄 통과하지 않음 |
| 반복 없음, 목록 끝 | 남은 미디어·타이머 종료 | 완료 |
| 전체 반복, 목록 끝 | 같은 확정 목록의 첫 그림으로 이동 | 재생 중. 빈 목록이면 시작 불가 |
| 구간 반복, 구간 끝 | 포함 범위의 시작 그림으로 이동 | 재생 중. 한 그림 구간도 허용 |
| 구간 시작이 끝보다 뒤/목록 밖 ID | 재생하지 않고 범위를 바로잡게 함 | 준비/일시정지. 자동으로 전혀 다른 구간 선택 금지 |
| 일시정지/정지 | 오디오 정지·남은 시간 보존 또는 초기화 규칙을 버튼별로 명확히 함 | 일시정지/준비. 예약된 다음 이동 취소 |
| 사용자가 수동 다음/이전/다른 그림 선택 | 기존 오디오·타이머 취소, 실행 토큰 갱신, 새 그림 표시 | 재생 중이었으면 새 그림에서 계속, 멈춰 있었으면 멈춤 유지 |
| 자동 넘김 끄기 | 이미 예약한 전환도 취소 | 현재 그림은 사용자 선택에 따라 계속 재생 가능, 끝에서 정지 |
| 재생 중 목록/반복 구간 바꾸기 | 먼저 일시정지하고 목록·범위를 새로 확정 | 과거 종료 이벤트가 새 목록을 움직이지 않음 |
| 이중 `ended`/이전 그림의 늦은 이벤트 | 실행 토큰과 현재 그림 ID가 맞지 않으면 무시, 한 실행의 완료는 한 번만 처리 | 한 번에 두 그림 넘어가지 않음 |
| 다른 탭으로 이동/화면 가림 | 그림 보기용 타이머를 멈추고 돌아오면 일시정지 상태 표시 | 보지도 않은 그림이 계속 넘어가지 않음 |

목록 반복은 제어기가 다음 그림 인덱스를 계산한다. 현재 TTS의 `end/error` 경로를 먼저 지원하고, 파일 음성이 있는 과에는 HTML audio 어댑터를 사용할 수 있다. 파일 음성의 `play()`/`ended` 규칙을 TTS에 그대로 적용하지 않는다. HTML audio의 `loop=true`로 목록 반복을 구현하지 않는다. 해당 옵션에서는 `ended`가 발생하지 않는 조건이 있어 다음 그림 전환과 충돌한다. 재생 권한이 거절되면 UI가 실제 재생 상태와 어긋나지 않게 한다.

## 9. 여섯 독립안과 일곱 번째 심사자의 운영

이 문서는 독립안 5이며, 스스로 다른 안의 우열을 판정하지 않는다. 향후 작업도 다음 구조로 운영한다.

1. 공통 사실 묶음·원본 그림·사용자 성공 사례·금지사항만 여섯 제안자에게 준다. 서로의 초안은 제출 전 볼 수 없게 한다.
2. 각 제안자는 동일 사실 묶음에 대해 소품·행동·연결·보존할 부분·실패 가능성·역회상 질문을 모두 제출한다. 취향만 다른 여섯 그림 프롬프트로 끝내지 않는다.
3. 일곱 번째 심사자는 원안을 그대로 보존하고, 후보별 채점표와 채택·기각 이유를 남긴다. 종합본에서 어느 안의 무엇을 썼는지 추적한다.
4. **사실 오류, 필요한 소품 미표현, 잘못된 인물/저서 귀속, 두드러진 다른 개념 회상, 필수 원문 누락**은 총점과 무관하게 반려한다.
5. 공통 평가 척도를 사용한다: 사실·출처 20, 단서 회상 가능성 25, 인물/저서/행위 관계 15, 교과서 범위·선행순서 15, 학습 부담·그림 수 10, 구현/검수 10, 근거·한계 5. 회상 항목 안에서 독음의 직접성·다른 단서와의 충돌을, 관계 항목 안에서 주체-행동-결과를 나눠 기록한다. 점수는 과학적으로 검증된 척도가 아니라 프로젝트의 의사결정 도구임을 밝힌다.
6. 모든 필수 차원을 통과한 후보만 제작 대상으로 넘긴다. 총점 예컨대 85점 이상을 잠정 기준으로 둘 수 있지만, **완성 이미지와 사용자 회상 검사 전에는 승인 완료가 아니다**. 같은 후보를 그림으로 만든 뒤 실재·가림·오해를 다시 채점한다.
7. 두 차례 수정에도 핵심 동작이 구현되지 않으면 탈락/보류로 보고하고, 이전 합격본 유지 또는 다른 표현 방식으로 전환한다. 횟수를 채우려고 실패작을 게시하지 않는다. 후보 재설계가 합리적이면 더 시도하되 중단 이유를 기록한다.

좋은 기존 사례의 이유는 단순하다. ‘전원 기립’은 많은 사람이 일어나는 하나의 행동에서 긴 설명 없이 발음이 나오고, ‘납작 까치’는 독특한 모양과 대상이 결합하며, ‘백설기→설기’는 익숙한 사물의 실제 독음 안에 목표가 들어 있다. 이를 새 후보에도 적용한다. 글자 뜻을 맞췄다는 사실만으로 자연스러운 음운 연결이라고 점수를 주지 않는다.

## 10. Opus 실행 순서와 완료 조건

### 1단계: 기준본과 누락 분모 확정

최신 Antigravity 폴더/커밋, 현재 배포본, DOCX 판본을 확인한다. HTML 안에 그림이 base64로 포함되었는지, 외부 경로인지도 파악한다. 접근 불가 파일과 누락 자산을 별도 목록으로 남긴다. 전수 결과의 분모를 원문 사실·본화·단서·대본·음성·연결 경로별로 제시한다.

수락 조건: 모든 파일에 식별 가능한 출처와 상태가 있고, 원문 항목마다 `그림으로 회상/문답으로 회상/보충 자료/미반영` 중 하나가 있다. 출전 미확인과 미검토는 “문제 없음”으로 세지 않는다.

### 2단계: 목차·선수관계·허브 네 기능

확정된 교재 목차에 링크를 배치하고, 기존 자료의 학습 순서를 먼저 안정화한다. 별표/썸네일/자동 넘김/반복을 위 상태 계약으로 구현한다. 모든 예술 자산 재제작을 기다리지 않아도 진행할 수 있다.

수락 조건: 잘못된 링크·빈 썸네일·없는 선수 ID가 0개. 별표는 새로고침·재정렬·그림 revision 교체 후 유지되고 export/import 후 동일해진다. 음성 있음/없음/차단/오류, 구간 한 장/여러 장, 끝 도달, 수동 전환 직전 종료 이벤트를 모두 확인한다. 별표 클릭이 그림을 열지 않고, 키보드와 모바일에서 동일 기능을 쓸 수 있다.

### 3단계: 어려운 사례로 제작 방식 검증

陶弘景, 王冰/啓玄子, 杜本/金鏡錄, 혈수 중복 359, 奇經 유주 한 쌍, 사암표 한 격, 醋法 한 목록을 시범으로 삼는다. 사실별 cue 커버리지와 역회상 실패를 기록한다. 이때 여섯 제안·일곱 심사를 적용한다.

수락 조건: 최종 픽셀에 목표 소품이 있고, 주체-행동-결과가 읽히며, 설명을 가린 상태에서 무엇이 회상되고 무엇이 안 되는지 보고한다. 실제 사용자 검사가 아직 없으면 “전문가/모델 평가 통과, 사용자 회상 미검증”으로 구분한다. 원문 누락 0은 주장할 수 있어도 기억 효과 100%를 주장하지 않는다.

### 4단계: 전 단원 확장과 기존 오류 회귀 검사

시범에서 통과한 표기·인물·숫자·장면 규칙을 전 영역에 적용한다. 우선순위는 사용자가 명시한 오류와 시험 관계의 누락이다. 이전 감사에서의 장면 가림, 사탕/땀 혼입, 대머리 인물 충돌, 위통처럼 보이는 肝脇痛, 노파/달밤과 얼음탕/한증막 불일치, 十問의 頭身, 현대 군복, 婦女/婦人 인용 충돌, 陽谿/解谿 등을 회귀 사례로 남긴다. 모든 사례를 새로 전수 시각 확인한 것처럼 보고하지 않는다.

수락 조건: 본화·단서·썸네일·음성·대본·문답의 revision이 일치한다. 답을 축약하며 원문 사실이 사라지지 않는다. 한자 이문은 출전에 따라 설명하고, 억지로 하나만 남기지 않는다. 파일 열기·이전 판 보기·구간 반복이 실제 산출물에서 작동한다.

### 5단계: 최종 보고와 인계

최종 보고에는 검토 분모/검토 완료 수, 수정·보존·교체 수, 남은 실패, 출전 보류, 미검토 영역을 각각 제시한다. 여섯 원안, 일곱 번째 채점 원본, 종합 최종안, 적용 manifest, 변경 로그를 함께 제공한다. 큰 단일 HTML 하나에 이미지를 모두 넣는 배포는 피하고, 사용자 환경에 맞는 상대경로 자산 묶음과 정상 실행 경로를 안내한다. 분할할 경우 각 묶음의 실제 크기·전체 구성·실행 방법을 검증한다.

“다 끝났다”는 표현은 사실·그림·기능 검사가 모두 충족된 범위에만 사용한다. 생성했지만 실패한 그림, 접근하지 못한 원문, 아직 사용자 회상 검증을 거치지 않은 후보를 따로 남기는 것이 이 프로젝트의 완료 조건이다.
