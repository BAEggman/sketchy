# Gemini 낭독 제작 실행계획 — 공개용

이 문서는 확정한 한의학 그림 대본을 음성으로 제작하고 검수하는 공통 절차다. 개인 세션 주소, 기기 경로, 다운로드 이력과 개별 실행 기록은 포함하지 않는다. 이 문서만으로 특정 계정의 현재 음성 생성 기능이나 파일 생성 성공을 보증하지 않는다.

## 현재 대본과 작업 범위

- 본편: 227과, 2,067구간. `narrations.json`의 `narration`이 이번 반말 검토 대본이다.
- 부록: 낭독 737행, 낭독에서 제외한 제작 메모 3행. 괘도 대본 2종을 합쳐 낭독문은 총 2,806개다.
- 본편 보류는 464구간이며, 보류 없는 1,603구간도 검토 초안이다. `ready_to_generate`는 전부 false다.
- 부록의 실제 그림 전수 대조와 `why` 필드에 섞인 추가 개념·제작 이력의 분리는 미완료다.
- 본편의 주요 그림 단서 검토 기록은 `visual-audit.json`, 수정 내용은 `narration-content-edits.json` 및 `post-conversion-review-edits.json`에 있다.

지금 작업은 대본 검토와 게시다. 음성 제작 단계에서는 남은 불일치와 보류 이유를 먼저 해결하고, 제작할 대본 버전을 확정한다. 보류 표시가 없다는 이유만으로 자동 통과시키지 않는다.

## 대본 확정과 니모닉 보존

1. 카드 ID, 현재 그림, 원자료의 정답·설명, 반말 대본을 대조한다.
2. 부정, 예외, 보·사, 수치·단위, 인물·저서, 본초·경혈 이름이 빠지거나 서로 바뀌지 않았는지 확인한다.
3. 사용자 니모닉과 말장난을 보존한다. 예를 들어 ‘45세부터 위가 약해진다’는 위경 45혈의 암기 이야기이므로 삭제하거나 다른 이야기로 바꾸지 않는다. 사실 설명과 암기 장면은 구분해서 전달한다.
4. `original_tts`, `source_station`, `source_row` 등 원본 필드는 보존한다. 녹음할 문자열은 `narration` 하나로 고정한다.
5. 수정한 카드와 이유, 수정 전후 문장, 대본의 SHA-256을 기록한다. 생성 중에 대본을 임의로 요약하거나 존댓말로 되돌리지 않는다.

## 대표 샘플부터 제작

현재 선택한 Gemini 화면에서 음성 파일 생성과 다운로드가 실제로 가능한지 확인한다. 가능할 경우 인명·저서명, 본초·혈명, 숫자·대조가 포함된 대표 카드 3개를 먼저 제작한다. 모델과 화자 선택은 화면에서 확인한 값을 기록한다. 존재를 확인하지 못한 모델명이나 기능을 가정하지 않는다.

처음에는 카드 1개당 음성 파일 1개로 진행한다. 여러 카드를 요청할 경우에도 카드별 파일과 대본의 대응을 확인할 수 있어야 한다. 응답에 파일이 없으면 성공으로 기록하지 않는다.

### Gemini에 전달할 요청문

```text
아래 [낭독 대본]만 한국어 음성 파일로 만들어 주세요.

작업 정보 — 읽지 마세요:
- 파일명: {card_id}__{audio_key_short}.wav
- 한국어 화자 한 명, 차분하고 또렷한 강의체.
- 인사, 제목, 파일명, 작업 번호, 설명을 덧붙이지 마세요.
- 단어와 순서를 바꾸거나 요약하지 마세요.
- ~한다, ~이다 형태의 반말 서술체를 그대로 유지하세요.
- 인명·저서명·본초명·혈명과 숫자를 정확히 읽으세요.
- 말장난과 암기 이야기를 삭제하거나 사실 설명으로 고쳐 쓰지 마세요.

[낭독 대본]
{narration}
```

이 요청문은 결과를 보장하지 않는다. 파일을 내려받은 뒤 실제 발화를 검사한다. 발음 표기는 사전에 확정한 발음 사전을 사용하며, 의미가 달라지는 대체 단어를 넣지 않는다.

## 파일 대응과 재생성 방지

카드 ID와 대본 해시를 기준으로 음성을 관리한다. 화자·모델·설정이 달라지면 별도 버전으로 기록한다. 캐시 키에는 대본 해시와 제작 설정을 포함한다. 이름이 같은 파일이라는 이유만으로 최신 대본의 음성으로 판단하지 않는다.

권장 작업 명세 항목:

| 항목 | 기록할 내용 |
|---|---|
| card_id | 원본 카드 ID |
| script_sha256 | 실제 낭독 문자열의 해시 |
| audio_key | 대본과 제작 설정을 묶은 버전 키 |
| audio_path | 게시할 상대 경로 |
| voice / model | 실제 사용한 화자와 모델 |
| duration_seconds | 파일에서 측정한 길이 |
| transcript_checked | 문장 누락·중복·바뀜 확인 결과 |
| listening_checked | 발음·잡음·잘림 청취 결과 |
| status | 대기, 제작, 검수, 보류, 완료 |

다운로드 알림만으로 성공이나 실패를 확정하지 않는다. 파일 존재, 크기, 실제 오디오 디코딩, 재생 길이를 확인한다. 반복 요청 전에 같은 카드의 파일이 이미 생성되어 있는지 확인한다. 실행 기록에는 작업에 필요한 최소 정보만 남기며 개인 경로나 세션 주소를 공개 저장소에 넣지 않는다.

## 음성 검수

모든 파일에서 대본과 발화를 대조한다. 특히 다음을 듣는다.

- 시작과 끝이 잘리지 않았는가.
- 문장·개념·예외가 누락되거나 중복되지 않았는가.
- 숫자와 단위, 보와 사, 원인과 결과, 표리 관계가 뒤바뀌지 않았는가.
- 한자 독음과 인명·혈명이 다른 단어로 들리지 않는가.
- 니모닉의 말장난이 유지되었는가.
- 인사, 파일명, 제목 같은 불필요한 말을 덧붙이지 않았는가.

전사 비교나 해시 검사는 청취 검사를 대신하지 않는다. 오류가 발견된 카드만 수정한 뒤 새 버전으로 다시 제작한다. ‘글자 수 감소’와 ‘실제 녹음 시간 감소’는 구분하며, 시간은 생성한 파일에서 측정한다.

## 학습 허브 연결

검수된 파일을 카드 ID와 대응시키고 그림을 여는 흐름에서 해당 음성을 불러오도록 연결한다. 재생 실패 시 수동 재생 버튼으로 이어질 수 있게 확인한다. 연속으로 다른 그림을 열었을 때 이전 음성이 겹치지 않는지, 같은 카드 재방문과 모바일에서 정상 재생되는지 확인한다.

클라이언트에 비밀 키를 넣지 않는다. 사용자가 그림을 열 때마다 새 음성을 만드는 흐름은 별도 설계가 필요하다. 여기서는 검수된 음성 파일을 미리 준비해 연결하는 제작 절차를 다룬다.

기존 `narration-review.html`에 있는 샘플은 이전 대본의 음성이다. 이번 반말판의 완성 파일로 재사용하거나 새 대본의 검수 완료 증거로 삼지 않는다.

## 완료 보고

실제 제작한 카드 수, 검수 통과·보류 수, 사용한 대본 버전, 파일과 카드의 대응, 게시 커밋, 재생 확인 결과를 보고한다. 확인하지 않은 파일을 완료로 세지 않는다. 미해결 항목은 카드 ID와 이유를 남긴다.
