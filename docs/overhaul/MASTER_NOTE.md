## 1. 사용자 · 상시 규칙

- 사용자는 한국어로 말하고, 대답도 한국어다. 결론부터 짧게 쓴다. 해 본 일과 확인한 것을 가른다.
- **역할**: 계획은 Fable 5.2가 썼다. 구현 · 실행은 Opus가 한다(사용자 11-20 지시).
- **올리기(push)는 사용자가 한다.** 클라우드에서 `git push`는 403이다. 우회하지 않는다. 올림 꾸러미(bundle)는 사용자가 원할 때 만든다. 예외: 대화를 넘길 때 작업을 잃지 않게 꾸러미를 Mac에 둔다(11-21에 한 것).
- 커밋 꼬리말(현재):
  ```
  Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
  Claude-Session: https://claude.ai/code/session_01MmBfjBsLabvgD3akaViY5Y
  ```
  새 대화의 시스템 알림이 다른 꼬리말을 주면 그것을 따른다. 커밋 이름은 `-c user.name="Claude" -c user.email="noreply@anthropic.com"`로 했다.
- 자격 증명 · API 키는 다루지 않는다. CAPTCHA는 사용자가 푼다. 영구 삭제는 사용자 확인 뒤에 한다. 사용자 이메일은 밖으로 내보내지 않는다.
- 사용자 지시(11-20, 계속 유효):
  - **사실을 지어내지 않는다.** 확인 못 한 것은 「확인 필요」로 적는다.
  - **사용자 암기 문장과 계획서 8절 보존 목록을 바꾸지 않는다.** 바꿔야 하면 먼저 묻는다.
  - **자동 판독 점수를 합격이라고 쓰지 않는다.**
  - 소품 · 상황 · 그림 간 연결을 짓거나 고치는 일은 모두 **6+1**로 한다. 여섯 독립 에이전트 → 여섯 안의 생각을 표로 보고 → 일곱 번째가 `runs/RUBRIC.md`(계획서 4-2 · 5-1 · 5-2)를 읽고 채점 · 합침. 원안 · 점수 · 채택과 탈락의 까닭을 `runs/<run_id>/`에 남긴다.
  - **P2 시범 여섯 가지가 끝나면 멈추고 사용자 검수를 받는다.** 「넓혀도 된다」 전에는 대량으로 그리지 않는다.
- 프로젝트 지시: 지속할 결과는 `project_write`로 프로젝트에 둔다. 색인은 `claude/Sketchy_작업기록_색인.md`(로컬 사본을 고쳐 `local_path`로 쓰기 전에 반드시 `project_read`로 현재 본문을 읽는다 — 안 읽으면 쓰기가 거절된다).

### 작업 방식 규칙 (사용자 11-21 18:32 · 18:35, 상시)
1. **답을 기다리며 멈추지 않는다.** 정할 것은 심사 추천을 기본값으로 진행하고 `DECISIONS.md`에 「기본값 적용」으로 남긴다(편집 전 그림 보존). 먼저 묻는 것은 넷뿐: ① 사용자 문장 · 8절 보존 목록 · 기존 결정을 바꾸는 것 ② 교재 근거가 갈리는 사실 ③ 과 신설 · 폐지 ④ 녹음 다시 만들기. 모아서 한 번에, 추천을 표시하고, 묻는 동안 그 소품만 보류한다.
2. **탭 셋을 비워 두지 않는다.** 편집 수로 고르게 나누고, 먼저 끝난 탭에 바로 다음 과를 준다. 일꾼이 도는 동안 본체는 브라우저가 필요 없는 일(과 JSON · 정거장 · 대본 · 빌드 · 검수 문항 · 커밋 · 다음 edits.json)을 한다.
3. **편집을 가볍게.** 맞닿은 구역 변경은 합친다(새 물건 ≤3). 클릭을 묶고, 스크린샷은 파일 이름 확인과 결과 확인 때만. 편집마다 시작 · 끝 시각을 log에. 평소의 두 배를 넘긴 시도는 끊고 새 채팅. 실패는 묶음 끝에 모아 다시.
4. **재시도는 그림이 완성될 때까지**(18:35, 「한 번만」 규칙 폐기). 셋째부터는 소품 · 동작은 그대로 두고 틀린 부분만 더 또렷이 적는다. 소품을 바꿔야 하면 「6+1 필요」.
5. **6+1은 가볍게.** brief에 다 넣고, 여섯 안은 brief · `runs/RUBRIC.md`만 읽고 JSON 1,500자 안. 여러 묶음의 여섯을 함께 띄운다.
6. **보고는 묶음 끝에 다섯 줄**(끝낸 과 · 실패/보류 · 정할 것 · 시간당 편집 수 · 다음). 점수표는 `runs/`에. CAPTCHA · 권한 필요는 즉시 알린다.
7. **건너뛰지 않는 것:** 교재 줄 번호로 확인된 사실만 · 소품 연결은 6+1 · 계획서 7절 관문과 사용자 검수 · 그림에 글자 · 숫자 없음 · 손이 책에 닿음 · 판정 기준 그대로 · 완성 그림은 본체가 직접 본다(자동 점수는 참고) · 실패 그림으로 게시본을 덮지 않음 · 원본 · 옛 판은 지우지 않음 · 과마다 커밋 · 묶음 끝에 STATE · DECISIONS · 색인 · zt 도구 · edits · log를 저장소에 · 대화를 끝내기 전 Mac에 꾸러미.
8. 첫 묶음 뒤 실패가 늘면 원인 규칙만 되돌리고 한 줄로 알린다.

## 7. 실무 메모 (값비싸게 배운 것)

- **클라우드 작업장은 사라진다.** 끝내기 전에 커밋하고 꾸러미를 Mac에 둔다. 스테이징 파일(`/mnt/user-data/uploads/…`)도 새 대화에서 다시 받아야 한다.
- Mac으로 보내기: 큰 파일은 `SendUserFile`로 `file_uuid`를 받은 뒤 `device_commit_files`에 그 uuid를 쓴다(stagedPath로 80MB는 실패했다).
- 서브에이전트(6+1)는 한 안에 10~17분 걸리고, 5시간 사용량 한도에 걸릴 수 있다. 11-20 심사자는 한도로 끊겼다가 `SendMessage`로 이어서 끝냈다. 여섯 안은 한 메시지에서 동시에 띄운다.
- Playwright: `require('playwright')`는 저장소 폴더 안에서 돈다(scratch에서는 모듈을 못 찾음). 시계는 `page.clock.install()` → `runFor`. 큰 webp는 `img.decode()`를 기다린 뒤 캡처해야 회색이 안 나온다. 헤드리스 Chromium의 읽어 주기는 실패하므로 소리 시험은 가짜 Audio · speechSynthesis로 한다.
- `build_player.py`는 녹음이 걸린 정거장 · 그림이 바뀌면 멈춘다(해시 검사). 녹음 과를 고칠 때는 낭독 트랙과 맞춘다.
- 교재 추출본의 8장 절들은 본문이 3~15줄뿐이라 용어 점수가 흔들린다. 줄 번호를 직접 찾는다.
- 교재 1638행 「秦 皇甫謐」은 오기(晉).
- **Gemini(Claude in Chrome)**: 「이미지 만들기」 · 16:9 · 「카본 높음」을 고른 뒤 프롬프트를 넣는다. 그림 한 장에 1~2분 걸린다.
  - 원본 내려받기는 그림 오른쪽 위 아이콘(「원본 크기 다운로드」)이다. 누른 뒤 **8~10초 기다린 다음** 다른 곳으로 옮긴다. 빨리 옮기면 받기가 끊긴다.
