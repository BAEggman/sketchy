# 낭독 시범 3장 (2026-11-22)

- 경로: Gemini 앱(Neon · 카본)은 두 번 모두 「이 채팅에서는 음성 파일을 만들 수 없다」로 거절했다(인계 §9 프롬프트, §8 원래 문형 둘 다). Google AI Studio의 Playground(generate-speech) 화면에서는 생성과 다운로드가 됐다. 키 발급·결제 설정은 하지 않았다. 쿠키 배너는 「나중에」.
- 음성: Kore (예전 첫 묶음 23구간과 같은 이름). 모델 표기 gemini-3.8-flash-tts는 화면 글자 그대로이며 공식 ID 확인은 안 했다.
- 시범 카드: hist-10#3(인명·저서), fan18-1#2(본초), suchi-10#7(숫자 되짚기).
- 검사: 파일 디코딩·길이·무음·피크(ffmpeg), Gemini 앱 받아쓰기 대조. 내 직접 청취 없음 → listening_checked=false. 재생기 연결(manifest) 안 함.
- 같은 날 녹음 전 대본 감사(runs/20261122-narr-audit/)에서 fan18-1#2 「칠정에도 두 번」이 교재 3495 生薑殺半夏까지 세면 세 번이라는 지적이 나왔다 — 대본이 바뀌면 이 시범은 다시 만든다.

## 2차 — Neon 태스크 방식 (사용자 지시 12:33 「예전에 하던 방식으로 neon 이나 carbon 에게」)
- Gemini 앱 **태스크** 모드 + Neon. 채팅 모드에서는 거절되지만 태스크 모드는 감수(읽기 방법 결정) → 녹음 → 재청취 → 필요 시 재녹음 → WAV 첨부까지 한다. 예전 성공 대화도 같은 방식.
- 프롬프트: NEON_TASK_PROMPT.txt. 결과: wav/neon_*.wav (24kHz 16bit mono). suchi-10#7은 Gemini가 1차의 「몰약은」「넷 위」를 고쳐 2차 녹음.
- 앞의 AI Studio 3장(감수 없음)은 쓰지 않는다. 다른 창에서 오타(틄) 섞인 입력으로 돌린 suchi-10 한 건도 쓰지 않는다.
- 내 직접 청취 없음. 사용자 청취 대기.

## 3차 — 목소리 고정 (사용자 12:42 「여성 목소리인데 일관성이 없어」 → Kore 선택)
- 프롬프트에 「반드시 Gemini TTS의 Kore 목소리(여성) 한 명으로만」과 「실제로 쓴 목소리 이름 보고」를 넣었다(NEON_TASK_PROMPT.txt, {notes} 자리에 과별 읽기 메모).
- 수정된 fan18-1#2(세 자리, 생강쇄반하)로 시험: Gemini 보고 「Kore」. wav/kore_fan18-1__s2__12f31c78b0c2.wav. 사용자가 예전 Kore 녹음과 비교해 확인할 것.
