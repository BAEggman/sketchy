## 1. 이 프로젝트가 무엇인가

한의학 국시 대비 암기를 위해, **한 장의 그림이 표 하나를 통째로 지도록** 설계한 니모닉 그림 라이브러리와 그 학습 허브다. 핵심 원칙은 한 줄이다 — **「그림이 사실을 설명하는 것이 아니라, 그림을 보면 사실이 떠올라야 한다.」** 그래서 판정의 1관문은 만든 사람의 자기 채점이 아니라 **답을 가린 제3자의 역방향 판독**이다.

칸은 네 트랙으로 갈린다: **A 서사**(누가 했나 — 소리 다리 + 왕조 자리) · **B 무대**(어디 속하나·몇 번째인가 — 자리가 곧 사실) · **C 카드**(이 하나가 무슨 성질인가 — 고정 격자 반복) · **D 도해**(전체가 어떻게 짜였나 — 자리·순서·개수가 정확해야 하므로 **코드로 그린다**). A·B·C는 생성 AI(Gemini 앱)로, D는 파이썬으로 만든다.

만든 것: 그림 110장 + 도해 23판(문항 335) + 함정 165행 + 규칙 174조 + 글자 사전 104자, 그리고 이것을 자가테스트·다리·함정·딥링크로 묶은 단일 허브 `index.html`. 곁가지로 Suno 암기송 21곡(사암 12 · 교회혈 7 · 계통 1 · 배수혈 1)과 SRS 덱 2016장이 있다.

### 2-2. 이 색인이 대체하는 문서들이 낳은 규칙 — 번호 + 한 줄 요지

**세트 4 상한·온병 (18~25)**
18 대화형 UI 연속 생성은 직전 그림을 편집해버린다 — 매 프롬프트 맨 앞에 「완전히 새 그림」 / 19 액자 덩굴 장식이 침입한다 / 20 상징을 약화시켜 지시하면 색까지 지워진다 — 약화는 굵기·연속성으로만, 색은 따로 못박는다 / 21 「옅게·희미하게」는 무시된다 — 형태로 서술하고 배수로 지정 / 22 상징 사전 충돌은 프롬프트에서 미리 배제한다 / 23 참조 체인은 배경까지 옮긴다 / 24 한 몸을 가르는 구도에서는 인물 분열이 안 난다 / 25 연속 패널은 복장을 고정하면 단계축이 살아난다

**세트 5 본초·방제 (26~30)**
26 편집의 한계선 — 소품 추가·색·제거·크기까지. 자세·신체 기호는 편집으로 안 된다 / 27 맥상은 어느 패널에도 곁다리로 넣지 않는다 / 28 양의 하한선도 배수처럼 쓴다 / 29 약재 이름에 색이 들어가면 어느 면의 색인지까지 쓴다 / 30 전송 버튼 두 번 클릭 = 생성 중지

**감사수정·세트 6 (31~35)**
31 새 대화창으로 옮기면 복장부터 무너진다 — 참조 이미지 + 복장 문장 둘 다 / 32 양손이 이미 찬 인물에게 셋째 손을 요구하지 마라 / 33 「두 사물 사이」는 좌표가 아니다 — 유일 특정 지점으로 / 34 작은 소품에 세 겹 색 사실을 얹지 마라 — 배수로 키운다 / 35 네트워크 실패는 편집 실패가 아니다

**보강·세트 7 설계 (36~38)**
36 「한 소품 = 한 사실」은 눈으로 못 지킨다 — 기계로 검사하라 / 37 그릇은 가구다 — 사실은 담긴 것이 나른다 / 38 사실이 이어진 소품 겹침은 위반이 아니라 딥링크다

**세트 7 병기 (39~45)**
39 대화창은 열 장쯤에서 이미지 생성 자체가 죽는다 / 40 복장 고정문은 매 프롬프트에 / 41 개수는 「한 자리에 모으고·수를 명시하고·겹치지 않게」 셋을 함께 / 42 원본 다운로드가 죽으면 blob 앵커로 / 43 크롬의 자동 다운로드 차단은 조용하다 / 44 판정에 다운로드는 필요 없다 / 45 매 프롬프트 전에 새로고침

**전수감사·캠페인 1·2차 (46~57)**
46 개수가 사실인 칸은 픽셀로 검산한다 / 47 만든 사람이 판정하지 않는다 / 48 복장 고정문은 세트 불문 전 프롬프트에 / 49 종횡비는 정사각형으로 / 50 판정관은 셋을 다른 렌즈로 / 51 다른 칸의 전담 기호를 쓰면 그 자체로 폐기 / 52 五化는 성숙도 순서가 그림에서 지켜져야 한다 / 53 그리기 전에 스펙부터 감사한다 / 54 벽과 옷은 「대비량」으로 규정한다(범위는 「색이 사실인 모든 칸」) / 55 불투명한 표시를 얹는 기호는 「덮인 화소」로 검산하지 않는다 / 56 정본의 표본으로 지목하는 칸은 실측해서 지목한다 / 57 「에워쌌다·얹혔다」를 화소 포함관계로 재지 않는다

**역방향 판독 (58~69, 67-b, 69-b)**
58 판정 1관문은 답을 가린 역방향 판독이다 / 59 「싫어함」은 정지된 대항 사물로 짓는다 / 60 「오래·많이」는 자국으로 못 나른다 / 61 소품이 그 장면에 있을 법하면 안 된다 / 62 얼굴이 옷보다 먼저 무너진다 / 63 금지 문구가 실제로 그 사물을 막는지 확인한다 / **63-b** 그 금지가 지키기로 한 것까지 막지는 않는지 반대로도 읽는다 / 64 한 칸 안 두 지시의 물리적 양립 / 65 지시를 고치면 checks도 고친다 / **65b** 줄을 지울 때는 그 줄이 지던 사실을 먼저 센다 / 66 무더기는 지금 쓰는 것과 같은 물건으로 / 67 비교 칸 — 다른 것이 하나뿐일 때만 그것이 사실이 된다 / **67-b** 같은 색이어야 하는 두 얼굴은 「같아야 할 것」과 「달라야 할 것」을 같은 문단에 / 68 광택은 화소로 못 잰다 / 69 prop 전수 검색은 규칙 61의 값싼 대용(**prop과 why 양쪽에서**) / **69-b** 같은 대화창에서 이어 그리면 인원수도 따라온다

**체계 복구 (70~78)**
70 트랙을 먼저 정한다 / 71 한 장면 = 한 표. 태그에 「기타」가 생기면 그 장면은 이미 실패 / 72 소리 다리 사물은 홀로 두지 않는다 / 73 충돌은 사물이 아니라 뜻의 개수로 센다 / 74 자리·순서·개수가 곧 사실이면 코드로 도해를 그리고, 도해에는 글자를 허용한다 / 75 거울 쌍을 적극적으로 만든다 / 76 규칙 47은 문서에도 적용된다 / 77 새로 발견하기 전에 이미 적혀 있는지부터 확인한다 / **78 도해를 만들면 그 사실의 무대 칸을 함께 정한다**

**사암 s18p09·s18p10 (39-b·39-c, 46~50, 79~84)**
39-b 이미지 생성은 계정 단위로 죽는다 — 열두 자짜리 프롬프트로 진단하라 / 39-c 이미지 유무를 `naturalWidth`로 세지 마라 / 46 전송 버튼은 두 번 누르면 취소된다 / 47 창 크기가 바뀌면 좌표가 통째로 어긋난다 / 48 진단은 판독자가, 처방은 §5 사전이 낸다 / 49 「아무 일도 없음」은 빈 자리로 못 짓는다 — 부재는 상태 값이 아니다 / 50 좌우를 평행한 두 블록으로 적으면 그림에 두 단 조판으로 인쇄된다 / 79 브라우저 안의 그림은 `zoom` + `save_to_disk`로 컨테이너에 내려온다 / 80 누를 자리는 스크린샷을 보고 잡는다 / 81 「가득 참=補」와 「가득 참+빗자루=瀉」를 한 그림에 두지 마라 / 82 대칭 구도에서 한쪽에만 있는 소품은 「끼워 넣은 것」으로 읽힌다 / 83 상태 기호와 그 오행 내용물에 같은 도형을 쓰지 마라 / **84 제미나이 그리기는 예약 실행(클라우드)에 절대 올리지 않는다**

**이미지 판독 전면검사 (146~160, 149-b)**

## 4. 잃으면 안 되는 것 — 이 색인에만 남는 내용

### 가. 도구·환경에서 값비싸게 배운 것

- **참조 이미지 첨부 우회 (2026-08-02)** — 제미나이 앱은 `input[type=file]`을 만들어 즉시 `.click()` 하고 버리므로 네이티브 파일 창 없이는 못 잡는다. **`HTMLElement.prototype.click`을 덮어써 파일 입력만 가로채 DOM에 붙잡아 둔다.** 단 `+` 메뉴가 뜨는 데 5~8초 걸리고 그 사이 입력하면 메뉴 검색창으로 들어간다.
- **`+` 업로드 메뉴는 통째로 죽고 새로고침으로도 안 풀린다** — 메뉴 컨테이너(`lm-menu-theme`)가 자식 0개인 빈 껍데기로 쌓인다. 새 탭·새 창도 소용없다. **우회로는 드래그 앤 드롭**(완전히 다른 경로라 메뉴가 죽어도 산다). 브라우저는 정책상 읽기 전용 권한만 나와 화면 제어 우회도 불가능하다.
- **첨부 썸네일을 지우려면 `aria-label`이 「첨부파일 닫기」인 버튼**을 눌러야 한다 — 썸네일 본체를 클릭하면 주석 편집기가 열린다.
- **한 메시지에 두 장을 붙이면 모델이 둘을 섞어 그린다.**
- **Gemini API 무료 등급에는 이미지 생성 모델 할당량이 아예 없다**(`limit: 0`). 결제가 없으면 `gen.py`는 어떤 이미지 모델로도 429를 받는다. → 앱(Pro 구독) 화면으로 우회. Nano Banana Pro = gemini-3-pro-image.
- **좌표 실측 (2026-08-15)** — 계산 k = 1247/1163 = 1.072 → 전송 버튼 (906,654)→(971,701) **빗나감**. 실측 k = 1067/906 = 1.178 → (906,654)→(1067,771) **적중**. JS 좌표계와 스크린샷 좌표계 사이에 `innerWidth`로는 알 수 없는 배율이 하나 더 있다.
- **`resize_window`로 1280×900이면 k=1.1123으로 안정**된다.
- **`__INS(txt)` = `execCommand('selectAll')` + `execCommand('insertText')`. Enter는 끝내 안 먹는다.**
- **`zoom` + `save_to_disk` 실측** — 1024짜리 정사각 그림이 **1092×1092로** 컨테이너에 내려온다. 원본 화소를 거의 안 잃는다. **이걸 몰라서 s18p09 v6을 완성해 놓고도 배포에서 통째로 뺐다.**

**(3) 세 판 연속 같은 병 — 체계 복구 설계서의 수업료**

> 지적된 대상은 고치는데 **그 자리에 새로 쓴 대체안이 또 다른 칸을 밟았다.**
> v2 「가장 안쪽 방」(→ s13p05 少陰의 자리) → v3-1차 「찬 뒤뜰」(→ s13p02 陽明의 마당) → v3-2차 「갈라지는 두 길」(→ s02p01[7] 표지판=시대 전환 + s06p01[6] 물길 한 줄기, 그리고 「발전사가 갈라진 것」으로 **의도와 정반대**).
> **대체안을 쓸 때마다 그 대체안으로 전수 검색을 한 번 더 돌린다.** 최종안은 「물길은 한 줄기 그대로 두고, 그 물 가운데 박아 세운 돌 하나」. 그리고 **곳간(s13p04)은 손대지 않았다 — 무대가 이미 가르고 있다.**

**(4) 등재하려다 취소한 규정**

- **「창고·방을 자리 기호로 쓰지 않는다」 등재 취소** — 그 문장이 바로 **자신이 보호하려던 s13p05 少陰의 「가장 깊고 어두운 방」을 금지**했다. → 규칙 63-b가 여기서 나왔다.
- **`Nothing is tied anywhere on his body`** 가 찰갑 엮음과 짚신 끈까지 지웠다.
- 규칙 78·79·80 신설안 기각 — 78은 CANON §5-1과 같은 주장, 80은 규칙 69 단서와 한 글자도 다르지 않았다.

**(5) 못 고치고 포기한 것**

- **s03p01 국수 十四** — 5회차까지 한 번도 14에 못 닿았고, 시도할수록 이웃 소품(왕관 골동상·진열장)을 가렸다. 마지막엔 가게 앞 국수줄이 하나 더 생겨 **王好古를 통째로 덮었다.** 되돌려 놓고 멈췄다. **「14는 어떤 배치로도 한눈에 안 세어진다.」** 규칙 122 포기 목록, 十四經의 수는 도해 `s18d01` 2문항이 진다. **s03p01 그림은 원본 그대로 두었다.**

### 라. 한의학 사실 — 원문 대조와 검산

**(1) 지어낸 고전 인용을 인쇄할 뻔한 것 (2026-08-15, 제3자 원문 대조가 잡음)**

> **「難經 六十六難 『陰經以兪爲原』」 — 六十六難에 그런 문구가 없다.**
> 六十六難의 실제 문장은 **「十二經皆以兪爲原者, 何也?」** — 열두 경 **전부**를 말한다.
> 陰陽을 가른 것은 후대 주석이다 — **滑壽 『難經本義』 註 「五藏陰經, 止以兪爲原; 六府陽經, 旣有兪, 仍別有原」.**

곁들여 나온 것 둘:
- 六十六難 자체가 **「心之原出於大陵」**과 **「少陰之原出於兌骨(神門)」**을 함께 싣고, 靈樞·九鍼十二原은 **「陽中之太陽, 心也, 其原出於大陵」**으로 神門을 들지 않는다. **지금 쓰는 心 原穴 = 神門은 후대 정리다.** 기출은 神門으로 묻는다(경락 3차분 Q172) — 원문을 직접 읽을 때만 부딪히는 자리라 함정 줄로 등재했다.
- **內關 조문 표점 이설 셋** — 「…循經以上系於心包絡心系」를 `系於心包, 絡心系` / `系於心包絡。心系…` / `系於心, 包絡心系` 로 끊는 판본이 있다. 글자열은 어느 판본이나 같아 셈(11 명시 / 心包 1 미명시)에는 영향이 없다.

**(2) 도해가 자기 설명문과 반대로 그려져 있던 것 셋 (2026-08-08)**

- **八綱 表/裏의 색이 자기 요약 띠와 정반대**였다 — 색으로 읽으면 「表=陰」이 된다. 게다가 表裏의 유일한 무대 자리가 하필 s13p02 「陽明 = 裏」(가장 헷갈리는 칸)라 오독이 두 겹으로 굳을 뻔했다.
- **直中 점선이 太陽 상자 밑변에서 출발**하고 있었다 — 그건 越經傳이지 直中이 아니다. **直中의 정의 전부가 「三陽을 거치지 않는다」인데 범례는 그렇게 적어 놓고 그림이 반대로 그렸다.**
- **相殺의 화살표가 자기 설명문과 반대**였다. 相畏와 相殺는 같은 사건의 두 이름(半夏畏生薑 = 生薑殺半夏毒)이라 화살표도 같은 방향이어야 한다. 그리고 **相惡을 「서로 깎는다」로 바꾼 것이 그 개정이 새로 넣은 오류**였다 — 相惡은 단방향이다(人蔘惡萊菔子).

**(3) 설계서가 도해보다 한 발 더 나가 틀린 것**

> **v1 설계서가 「熱格 = 瀉火」로 쓸 뻔했다.** 참인 것은 **3경(大腸·心·三焦)뿐**이고 **9경에서 거짓**이다. 도해 `s18d07`이 이미 「肺 熱格 瀉 태백·태연(土)」로 옳게 적어 놨는데 설계서만 앞서 나갔다 — 규칙 77 위반의 교과서적 사례.

### 아. 출제·학습 데이터 메모

- **허브 로그가 반쪽이다** — 「틀린 횟수」는 있고 **「시도 횟수(`seen`)」가 없다.** 55회가 55/60인지 55/300인지 모르면 오답률을 못 낸다. **자주 나오는 문항일수록 절대 오답 수가 크다.** → **D절 숫자로 개별 칸의 품질을 판정하지 않는다.**
- **그래서 실제로 한 번 틀렸다** — 「오답 횟수가 소리 다리 개수와 거꾸로 간다」고 썼는데, **吳謙은 소리 다리가 다섯인데 55회, 이규준은 0인데 7회.** 거꾸로가 아니라 오히려 같은 방향이었다.
- **그린 칸이 나빠서가 아니라 안 그린 곳이 틀린다** — 최약 60장 × 86칸 결합(2026-08-08): **그림이 아예 없다 51장(85%) / 오답 295회(88%)** ↔ 그려져 있는데도 틀린다 9장(15%) / 40회(12%). 경락 140 + 장상 32 = **172회(51%)가 그림 0칸 과목**이었다.
- **가장 안 외워지는 덩어리 둘이 그림이 아니라 「표」다** — 舍岩鍼法 38회 · 背兪穴·募穴 21회. 五輸穴 7 + 경락사 9를 더하면 **75회분이 전부 도해**다.
- **정확성 ≠ 기억.** 사암침법은 기본서에 표가 있고 Suno 암기송 12곡까지 있는데도 **38번 틀렸다. 표가 없어서 못 외운 것이 아니다.** 네 번째 표를 더 얹는 것은 아무것도 바꾸지 않는다 → 규칙 78.
- **醫宗金鑑은 s04p02의 맨 첫 행에 「★허브 오답 1위」라고 스스로 적어 놓고도 55번 틀렸다.** 그림이 있다 ≠ 외워진다.
- 정답해설 원문 오류 1건 확인 — **정기신혈진액 3차분 Q148 (氣脫者耳聾 ↔ 精脫者目不明).**
- 앱 데이터 독음 불일치 — **`肓俞`가 「황수」, `臑俞`가 「노유」.** 같은 `俞`가 다르게 읽혀 있어 교재 대조가 필요하다(가사는 앱 데이터를 그대로 따랐다).
