## 1. 화질 — 진짜 원인은 화면 배율이었다

사용자 지적으로 다시 파고들어 원인을 정확히 잡았다.

| | |
|---|---|
| 패널 표시 폭 | 910 CSS px |
| 화면 배율 | **2×(Retina)** → 실제 필요 화소 **1820** |
| 원본 폭 | **1024px** (제미나이 생성 천장, blob 실측) |
| 확대율 | **1.78배** |

**앞서 한 「80판 복원」은 크기만 올린 것이었다.** git 이력의 1100~1250px 판본을 검사하니
옛 1024를 LANCZOS로 늘린 것과 화소차 중앙값 **2.49/255**, 고주파 에너지 0.1654 vs 0.1641 —
**실제 디테일이 하나도 더 없었다.** 규칙 159대로 그림을 화면 캡처로 받아 왔기 때문이다.

**처방** — 110장 전부 Real-ESRGAN(anime 모델)으로 **2048px** 생성.
- 88판은 ESRGAN 채택, 오히려 뭉개진 22판은 LANCZOS+샤픈으로 따로 처리
- **옛 판보다 흐려진 것 0판**(전수 측정) · 총 20.5MB · 외부 파일이라 10MB 예산 무관
- 확대 1.78배 → **축소 0.89배**로 바뀌어 확대가 사라졌다

## 3. 望色 재작도 — 규칙 92-c

**92-c** 색으로 짓는 사실은 **「그 색이 아닌 것」이 같은 그림 안에** 있어야 성립한다(92-b의 색 확장).
근거: 望色 6판이 3:3으로 깨끗이 갈렸다 — ✓난 셋(赤·黃·黑)은 화면에 그 색 아닌 것이 있고, △난 셋은 없다.

### s12p01 靑色主病 — 완료 (제미나이 3회)
- 얼굴 전체의 푸른색을 지우고 **바탕은 창백한 살색**, 靑은 넷 다 다른 자리에:
  寒=입술·손끝 / 痛=맨살의 쇠못 둘레 / 瘀血=脣甲靑紫+검붉게 굳은 덩이 / 驚風=미간·콧대 뿌리
- **내용 교정**: 표준은 寒·痛·**瘀血**·驚風인데 이 판은 **驚風을 風과 驚으로 쪼개고 瘀血을 빠뜨렸다.**
  그 쪼갠 風(창밖 바람+커튼)이 **破傷風 유령의 재료**였다 — 내용 오류와 판독 실패가 같은 뿌리.
  근거: 7장 병인학설 「구어에는 … **脣甲靑紫**」 · 素問·金匱眞言論 「東方靑色 … 其病發驚駭」

### s12p04 白色主病 — 완료 (제미나이 3회)
- 진단이 s12p01과 달랐다. 대비는 **이미 있었다**(입술색 셋 다 다름). 진짜 원인은:

| | 하위형 이름 | 이름이 색을 되불러 주나 |
|---|---|---|
| s12p03 黃 ✓ | 萎**黃**·陽**黃**·陰**黃** | 그렇다 |
| s12p04 白 △ | 氣虛·陽虛·失血 | **아니다** → 가장 강한 기호(피 밴 천)가 표제어를 훔침 |

- 처방: 셋이 **똑같은 흰 사기대접**을 뺨 옆에 들어 「보통 흰색」의 **자**를 화면에 세우고,
  붉은 핏자국을 삼분의 일로 줄였다.

## 4. 이번에 확인한 도구 지식
- **제미나이 입력창에 Enter는 전송이 아니다** — 여러 줄 지시가 첫 줄에서 잘려 엉뚱한 그림이 나온다.
  한 줄로 쓰고 `execCommand('insertText')` 후 **「메시지 보내기」 버튼 click()**.
- **파일 입력은 「파일 업로드」에 hover해야 생긴다.** accept="image/*"인 것을 고른다.
- **제미나이 출력 천장은 1024×1024**(blob 실측).
- **Chrome 다운로드가 연결 폴더로 오지 않는다** · **base64 JS 반환은 차단**.
  → 이미지를 띄우고 **zoom + save_to_disk**로 컨테이너에 받는다. 다만 zoom의 region 좌표가
  CSS px와 1:1이 아니라 잘리므로 **요청 영역을 1.3배쯤 크게 잡고 나중에 흰 여백을 잘라낸다.**
- 제미나이 출력에 **✦ 워터마크**가 들어간다 — 소품으로 오독되므로 국소 인페인팅으로 지운다.
