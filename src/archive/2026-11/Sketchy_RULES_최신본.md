## 1. 프롬프트 표준형

모든 프롬프트는 **[스타일 블록] + [가드 문장] + [장면 서술]** 3층. 스타일 블록은 한 글자도 바꾸지 않는다(화풍 통일이 상징 사전의 전제).

```
Hand-drawn educational mnemonic illustration. Ink linework with soft watercolor washes.
Muted earthy palette — dusty teal, warm ochre, brick red, grey — except signal colors, which stay vivid.
Flat even lighting, plain off-white background. Slightly cartoonish figures with clear silhouettes.
Every object distinctly separated and readable. Single square panel.
No text, no letters, no numbers anywhere in the image.
No extra props, no unrelated tools, no decorative clutter.
```

**가드 문장** — 장면에 해당하면 반드시 추가:
- `Exactly N people in the scene.` — 인물 수 고정 (분열·군중 방지)
- `The room contains no furniture except what is described.` — 여분 가구가 다른 패널의 사실을 오염시킴
- `The window is closed and the curtain hangs perfectly straight and still — no wind anywhere.` — 風은 특정 패널 전용 신호
- `The folding screens show ONLY the backdrops described below — no [이전 패널 배경].` — 참조 이미지 배경 이월 차단
- `No people in this image — only [사물].` — 도표형 패널
- 편집 지시에는 **항상** `Do not add any text, letters, or numbers.`

**절대 금지**:
- 프롬프트에 아라비아 숫자를 쓰지 말 것 → 그림에 그대로 전사된다. 한글/영어 수사로 쓴다.
- 괄호 주석("글자 대신 잔선으로") 금지 → 주석 문구가 그림에 글자로 박힌다.
- 항목 번호(①②③)를 쓸 거면 `아래 번호는 배치 설명일 뿐이니 그림에 표시하지 마` 를 반드시 병기.
- "도장이 찍혀 있고" 같은 표현 금지 → 가짜 한자 인장이 생성됨. **물체로** 기술("방석 위에 옥새 도장이 놓여 있다").

**소품 4~8개.** 12개 이상은 반드시 실패 → 패널을 쪼갠다. **한 소품 = 한 사실.**

## 2. 실패에서 역산한 9규칙

1. **낯선 배치는 익숙한 장면으로 수렴** — 예외를 그리려면 정상 사례를 여럿 깔고 하나만 다르게.
2. **안 시킨 소품이 들어온다** — 가드 문장 상시 부착.
3. **가로 나열은 여백이 생긴다** — 파노라마는 화면을 꽉 채우라고 명시.
4. **없는 것은 명사로 지정** — "定位"→바닥의 발자국 표시, "無風"→감긴 깃발, "오래 걸음"→닳은 원형 자국.
5. **개수는 못 센다** — 개수 차이는 자리·방향으로 변환(2×2 격자 등). 생성으로 개수 교정 2회 실패하면 즉시 중단.
6. **개수가 시험 포인트가 아닌 경우가 많다** — 먼저 "이 숫자가 갈림목인가" 묻고, 아니면 라벨로 얹는다.
7. **참조 이미지는 구조물도 옮긴다** — 제거 지시할 때 ①그 자리에 무엇이 남는지 ②**제거되는 인물이 들고 있던 사실을 누구에게 재지정할지**까지 쓴다(땀이 사라진 사고의 원인).
8. **크기·길이는 배수로** — "clearly larger" 무시됨. `at least twice as large`.
9. **이름이 형태로 풀리면 최우선** — 한자를 사물 형태로(§4).

## 3. 40패널에서 새로 추가된 교훈

10. **인물 분열** — 한 인물에게 방향이 상충하는 동작 둘을 시키면 모델이 사람을 복제한다. 해결: ①도구로 양립시킨다(앉아서 책 보며 **긴 막대로** 화로 밀기) ②표적을 같은 방향에 모은다(타구를 물그릇 옆으로).
11. **편집 부작용** — 어떤 기호를 제거하면 같은 기호를 쓰는 옆 인물이 흔들린다(금메달 제거 → 옆 사람 왕관이 벗겨짐). 편집 후엔 **지시하지 않은 요소까지 전수 재검수**.
12. **편집 무응답** — 동일 이미지가 반환되면 1회 재시도, 또 실패하면 전체 재생성으로 전환. 3회 이상 태우지 않는다.
13. **편집이 장면을 다시 그리는 실패** — 인물·화풍·핵심 소품이 통째로 바뀌면 그 결과는 참조 이미지로도 쓰지 말고 폐기.
14. **대비 패널** — "같은 색인데 무엇이 갈리는가"가 시험 지점인 단원(望色, 太陽中風/傷寒)은 한 칸에 2~3인을 나란히 놓아 대비 자체를 사실로 만든다.
15. **격자 도표 패널** — 맥상처럼 감각을 다루는 항목은 서사보다 좌표. 사람 없이 사물 2×2.
16. **우연의 편입** — 의도 밖 결과가 사실과 맞으면 라벨로 흡수한다(발자국 청/적 → 天陽地陰, 바닥에 차버린 이불 → 實熱 증거).
17. **패널 간 간섭 검수** *(예외: 방제 패널의 필수 구성 약재는 중복 허용, 단 rows에 교차 링크 명기 — 예 桂枝 s13p01↔s14p08)* — 새 패널이 기존 패널의 인물·색·소품과 겹치면 사실이 섞인다. 예: 氣虛(淡白)가 누렇게 나와 脾虛(萎黃)와 충돌 → 색 교정 필수.

## 3-1. 세트 4(상한·온병 10패널)에서 새로 추가된 교훈

18. **대화형 UI 연속 생성은 직전 그림을 편집해버린다** — 같은 대화창에서 이어 그릴 때 장면 서술만 주면 모델이 새 그림을 그리지 않고 직전 패널을 고친다. 매 프롬프트 맨 앞에 반드시 붙인다:
    `Draw a completely new picture. Do not edit or reuse the previous image — only keep its art style exactly.`
19. **액자 장식이 침입한다** — 지시하지 않은 덩굴·잎 장식이 테두리 네 귀퉁이에 생긴다. 스타일 블록의 "no decorative clutter"로는 못 막는다. 발견하면 **장식만 제거하는 편집**(인물·소품 전부 유지 명시). 기존 패널의 밋밋한 테두리와 어긋나면 화풍 통일이 깨진다.
20. **상징을 약화시켜 지시하면 색까지 지워진다** — "거의 마른 냇물"이라고 쓰면 §5의 파란 냇물이 흐린 먹선이 되어 상징으로 안 읽힌다. **약화는 굵기·연속성으로만 지시하고 색은 따로 못박는다**: "가늘고 끊어졌지만 분명한 파란색".
21. **"옅게·희미하게"는 무시된다** — 斑疹隱隱을 `faint`로만 쓰면 또렷한 붉은 점으로 나온다. §2-8의 배수 원칙을 색·농도에도 적용한다: ①`blurred edges, barely showing through the skin` 처럼 **형태로** 서술하고 ②대비 패널이 있으면 `at least three times as many, clearly darker` 처럼 **배수로** 지정한다.
22. **상징 사전 충돌은 프롬프트에서 미리 배제한다** — 같은 사물이 다른 뜻으로 쓰인 전례가 있으면(무소뿔 = 犀燭 서명 vs 犀角 본초) 구별 요소를 명시적으로 뺀다: "무소뿔만, 촛불 없이, 타는 것 없이". 사후 검수보다 사전 배제가 싸다.
23. **참조 체인은 배경까지 옮긴다** — 무대가 바뀌는 첫 패널(예: 성벽 → 진료소)에는 `Do not reuse the [이전 무대] background from the earlier pictures.` 를 붙인다. 이 문장 하나로 성벽·돌방 이월이 완전히 차단됐다.
24. **인물 분열은 "한 몸을 가르는" 구도에서는 오히려 안 난다** — 半表半裏(좌우 분할)·上熱下寒(상하 분할) 둘 다 분열 없이 1인으로 나왔다. §3-10의 분열은 *상충하는 동작 둘*을 시킬 때 나는 것이지, *한 몸에 상반된 상태 둘*을 칠하는 것은 안전하다. 겁내지 말고 대비를 한 인물에 담아라.
25. **연속 패널은 복장을 고정하면 단계축이 살아난다** — 溫病 4패널에서 `the same man in the same clothes` 를 유지하니, 같은 인물이 문가 → 방 중앙 → 안쪽 → 구석으로 이동하는 것만으로 衛→氣→營→血의 심도 전변이 자리로 표현됐다. 단계형 단원에 재사용할 것.

**환경 주의** — Gemini API 무료 등급에는 **이미지 생성 모델 할당량이 아예 없다**(`limit: 0`). 프로젝트에 결제가 붙어 있지 않으면 gen.py는 어떤 이미지 모델로도 429를 받는다. 결제가 없으면 Gemini 앱(구독) 화면으로 우회한다.

26. **편집의 한계선** — 편집이 해내는 것은 소품 추가·색 변경·요소 제거·크기 조정까지. **인물의 자세·신체 방향을 바꾸거나 없던 신체 기호(맥진 자세 등)를 새로 얹는 것은 편집으로 안 된다.** 1회 실패 시 즉시 라벨·딥링크로 전환하고, 그 사실이 필수라면 처음부터 별도 패널로 분리한다. (근거: s13p01·s13p02 맥 기호 3회 실패)
27. **곁다리 금지 항목** — 맥상은 어느 패널에도 곁다리로 넣지 않는다. s12p09·s12p10 두 격자 패널이 전담하고 다른 패널은 딥링크만 건다. 감각 기반 기호는 서사 패널에서 매번 판독 실패한다.

## 3-3. 세트 6(병인)에서 새로 추가된 교훈

28. **연속 대화창은 여덟 장쯤에서 느려진다 — 그래도 옮기지 마라** — 이미지가 쌓이면 이미지 뒤에 딸려 오는 설명 텍스트 스트림이 몇 분씩 멈추고, 그 동안 전송 버튼이 정지 버튼으로 바뀌어 다음 프롬프트를 넣을 수 없다. **해법은 새 창이 아니라 페이지 새로고침이다** — 새로고침하면 멈춘 스트림이 풀리고 전송 버튼이 돌아온다. 새 창으로 옮기면 복장·인종·시대를 잃고(규칙 31) 그 복구 비용이 대기 시간보다 크다.
29. **다운로드 토스트가 전송 버튼 클릭을 먹는다**(규칙 30의 정확한 원인) — 토스트는 화면 왼쪽 아래에 뜨지만 전체 폭 오버레이라 오른쪽 아래 전송 버튼까지 덮는다. **다운로드 직후에는 반드시 토스트를 닫고 다음 프롬프트를 보낸다.**
30. **무대를 고정하면 계절이 사실을 나른다** — 연속 패널에서 인물뿐 아니라 **배경 구조물**(초가집·나무·길)까지 고정하면, 계절 변화만으로 배속이 표현된다. 六淫 여섯 칸이 봄·겨울·여름·장마·가을·화재로 흐르며 風春木 / 寒冬水 / 暑夏 / 濕長夏 / 燥秋金 / 火 를 라벨 없이 날랐다. 五運六氣·六氣 단원에 이식할 것.
31. **부득이 새 대화창으로 옮기면 복장부터 무너진다** — 스타일 블록은 화풍(선·채색·팔레트)만 고정할 뿐 **복장·인종·시대는 고정하지 않는다.** 대화창을 옮길 때는 ①직전 패널을 참조 이미지로 첨부하고 ②프롬프트에 복장을 문장으로 명시한다. 둘 중 하나만으로는 부족하다. (근거: s15p09가 현대 티셔츠 차림·서양인 얼굴로 나와 폐기 — 원래 대화창에서 복장을 명시해 재생성하자 즉시 통과)

**참조 이미지 첨부는 이제 가능하다** — 앱이 만들자마자 버리는 `input[type=file]` 을 `HTMLElement.prototype.click` 가로채기로 붙잡아 두면 네이티브 파일 창 없이 첨부된다. 단 + 메뉴가 뜨는 데 5~8초 걸리고 그 사이 입력하면 메뉴 검색창으로 들어가므로, 메뉴가 뜬 것을 눈으로 확인한 뒤 클릭한다.

## 3-4. 보강 세트(기존 7건 편집)와 세트 7 설계에서 새로 추가된 교훈

32. **규칙 26(자세 편집 금지)의 진짜 한계선은 「손의 개수」다** — 편집으로 안 되는 것은 *없던 신체 기호를 새로 얹는 것*이고, *이미 있는 사지의 각도를 조이거나 펴는 것*은 1회 편집으로 된다. 지시 전에 **"이 동작에 손이 몇 개 필요한가"**를 세어 보면 둘이 갈린다. 맥진 자세가 세 번 실패한 것은 두 손이 이미 약재를 쥐고 있어 셋째 손이 필요했기 때문이고, 收引(어깨·팔·무릎 세 관절 동시 변경)이 한 번에 된 것은 새 손이 필요 없었기 때문이다. (근거: s13p01·s13p02 3회 실패 ↔ s15p02 1회 성공)
33. **제미나이 `+` 업로드 메뉴는 통째로 죽을 수 있고, 새로고침으로도 안 풀린다** — 버튼을 눌러도 메뉴 컨테이너(`lm-menu-theme`)만 자식 0개인 빈 껍데기로 쌓인다. 새 탭·새 창도 소용없다(규칙 28의 스트림 정지와는 다른 증상). 화면 제어 우회도 불가능하다 — 브라우저는 정책상 읽기 전용 권한만 나온다. → **우회로는 드래그 앤 드롭이다.** `+` 메뉴와 완전히 다른 경로라 메뉴가 죽어도 살아 있다.
34. **한 메시지에 두 장을 붙이면 모델이 둘을 섞어 그린다** — 실수로 두 장이 붙었으면 썸네일 위 X 로 하나를 뗀다. 단 **썸네일 본체를 클릭하면 주석 편집기가 열리므로**, 지우려면 `aria-label` 이 "첨부파일 닫기"인 버튼을 눌러야 한다.
35. **편집 지시는 "Edit the attached picture of …" 로 대상을 한 구절로 특정한다** — 같은 대화창에서 여러 패널을 이어 편집할 때 이전 그림을 잘못 잡는 사고가 사라진다.
36. **「한 소품 = 한 사실」은 눈으로 못 지킨다 — 기계로 검사하라** — 스펙을 다 짠 뒤 소품 문자열별로 fact 집합을 뽑아 **원소가 둘 이상이면 위반**으로 잡는다. 세트 7에서 여섯 건이 걸렸고 그중 둘(깃발=출전↔무풍, 김=氣↔찬 기운)은 읽어서는 끝까지 못 찾았을 것이다. 검사 전에 **축과 위반을 구분할 기준**을 먼저 정한다 — 같은 사물의 상태 차이(덩굴의 크기, 냇물의 잦아듦·막힘·범람, 이불의 끌어안음·걷어참)는 §4 축이라 허용이고, **뜻 자체가 갈리는 것만** 위반이다.
37. **그릇은 가구다 — 사실은 담긴 것이 나른다** — 그릇·접시·사발이 여러 칸에 나오면 그릇마다 뜻을 붙이려 들지 말고, row 의 `prop` 문자열이 **내용물이나 부어지는 동작**을 가리키게 쓴다. 그릇 자체가 사실을 지는 자리는 세트에 하나도 두지 않는다. 다만 오줌만은 요강으로 고정한다(§5 확장).
38. **소품이 겹쳤을 때, 사실이 이어진 것이면 겹친 채로 두고 다리에 적는다** — 꺼져가는 등불은 s13p05 少陰과 s16p06 亡陽에 같은 형태로 나오는데, 등불의 뜻은 양쪽 다 「불꽃의 크기 = 陽氣의 양」으로 하나다. **少陰病이 끝까지 간 자리가 곧 亡陽**이므로 이것은 위반이 아니라 딥링크다. 억지로 다른 소품을 만들면 오히려 기호가 둘로 갈라진다. 판정 기준은 표제어가 아니라 **소품이 가리키는 뜻**이다.

→ **瀉는 「빗자루를 더한 補」로 짓지 않는다.** 한 그림 안에서 補와 瀉가 **같은 내용물**을 쓸 때는,
   빗자루 하나에 뒤집기를 다 맡기지 말고 **그릇 자체가 달라 보이게** 해야 한다(기울어짐·쏟아진 자국 등 — §5 등재 뒤에).

**82. 좌우 대칭 그림에서 한쪽에만 있는 소품은 「뜻」이 아니라 「나중에 끼워 넣은 것」으로 읽힌다.**
판독자 둘이 같은 말을 했다 — 「그림 전체가 엄격한 좌우 대칭인데 **빗자루만 짝이 없어서**, 장면에 원래 있던 살림살이가 아니라 뜻을 담으려고 끼워 넣은 물건처럼 보인다」.
→ 대칭 구도에서 **비대칭인 사실**을 지려면, 그 비대칭을 **소품 하나의 유무**로 짓지 말고 **양쪽에 다 있는 소품의 상태 차이**로 짓는다.

**83. 큰 기호와 그릇 속 내용물에 같은 도형을 쓰면 층위가 섞인다.**
「사람 곁의 큰 눈송이(상태 = 寒證)」와 「그릇에 담긴 작은 눈송이(약 = 水)」가 같은 육각 도형이라, 판독자 둘 다 **「공중의 눈송이를 그릇에 퍼 담아 놓은 것」**으로 읽었다.
불꽃 쪽은 안 섞였다 — 큰 것은 매끈한 불꽃 기호, 그릇 속은 **검은 숯덩이**라 생김새가 달랐기 때문이다.
→ **상태를 나르는 기호와 그 오행을 나르는 내용물은 서로 다른 사물로 짓는다.** (水: 큰 눈송이 ↔ 그릇에는 **맑은 물/얼음 조각**)

## 6. 판정 절차 (Cowork가 이미지를 보고 스스로 수행)

1. **대응표 전수 대조** — 스펙의 rows에 적힌 소품이 하나도 빠짐없이 그림에 있는가.
2. **글자 검사** — 한글·한자·숫자·인장 무늬가 하나라도 있으면 그 항목만 지우는 편집.
3. **인물 수** — 스펙과 일치하는가(분열·군중 여부).
4. **간섭 검사** — 이전 패널의 배경·소품·색이 이월돼 다른 사실을 오염시키는가.
5. **개수 사실** — 개수가 사실인 요소는 세어 본다. 틀리면 §2-5 정책(2회 실패 시 중단, 라벨로 처리).

판정: **통과** / **조건부**(편집 1~2회) / **반려**(전체 재생성).
조건부·반려 사유는 로그에 남긴다(다음 패널 프롬프트에 가드로 반영).
