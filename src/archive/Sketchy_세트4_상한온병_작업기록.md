## 이번 세트의 핵심 발견

**조건부 6건 중 4건이 "소품은 있는데 사실로 안 읽힘"이었다.** 틀린 소품이 들어온 사례는 0건. 즉 프롬프트의 소품 목록은 이미 충분하고, 부족한 건 **판독 강도**(색·굵기·농도)의 하한선이다. 다음 세트 프롬프트는 여기에 힘을 써야 한다.

- 浮脈이 피부에 붙은 혈관처럼 그려짐 (s13p01)
- "거의 마른 냇물"이 §5 공용 상징의 파란색까지 잃음 (s13p05)
- 얇은 흰 설태가 아예 안 보임 (s13p07)
- 斑疹隱隱이 뚜렷한 붉은 점으로 나옴 (s13p09)

**인물 분열 예측이 빗나갔다(좋은 쪽으로).** 사전에 위험 1·2순위로 찍은 s13p03(半表半裏 좌우 분할)·s13p06(上熱下寒 상하 분할)이 둘 다 분열 없이 통과. §3-10의 분열은 상충하는 *동작* 둘을 시킬 때 나는 것이지, 한 몸에 상반된 *상태* 둘을 칠하는 것은 안전하다.

**단계형 단원의 공식을 찾았다.** 溫病 4패널에서 같은 인물·같은 옷을 고정하고 자리만 문가 → 방 중앙 → 안쪽 → 구석으로 옮기니, 衛→氣→營→血의 심도 전변이 서사 없이 자리만으로 표현됐다. 六淫 전변·三焦辨證·병기 심화에 그대로 이식 가능.

## 환경 (다음에 다시 겪지 않도록)

- **Gemini API 무료 등급에는 이미지 생성 모델 할당량이 아예 없다** (`limit: 0`). 프로젝트에 결제가 없으면 `gen.py`는 3-pro-image·2.5-flash-image 모두 429를 받는다.
- 그래서 이번 세트는 **Gemini 앱(Pro 구독)** 화면에서 생성했다. Nano Banana Pro = gemini-3-pro-image.
- 참조 이미지 첨부는 앱의 파일 선택창을 자동으로 열 수 없어 불안정했다. **같은 대화창에서 연속 생성**하는 방식으로 대체했고, 이게 스펙의 참조 체인과 사실상 동일하게 작동했다.
- `confirm.py` / `build_local.py`는 네트워크가 필요 없어 맥에서 러너로 실행.
