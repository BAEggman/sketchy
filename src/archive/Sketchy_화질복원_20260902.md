# Sketchy 허브 화질 복원 — 그림을 파일로 분리 (2026-09-02)

사용자 지적: **「html sketchy 허브의 이미지 품질이 굉장히 나빠졌는데 원상복구가 안되겠니?」**
→ 원상복구했다. 그리고 다시 나빠지지 않을 구조로 바꿨다.

## 왜 나빠졌나 — 내 재작성 탓이 아니었다

먼저 의심한 것은 8월 31일 내가 `build_local.py` 를 다시 쓴 것이었다.
e190093 판본과 현재 그림을 대조하니 **106장이 바이트 단위로 동일**했다 — 재작성은 무죄다.

진짜 원인은 **예산 사다리**였다. GitHub 웹 업로드는 한 번에 **10 MB**가 상한이고
(`file_upload` 도구도 같은 10 MB), 단일 파일 허브는 그림 110장을 base64로 품는다.
base64는 원본 바이트를 **4/3배**로 부풀린다. 패널이 늘 때마다 사다리가 한 칸씩 내려가며
해상도와 품질을 깎았고, 그 손실이 몇 달에 걸쳐 쌓였다.

되살린 원본 8.2 MB는 base64로 **11.3 MB** — 다리를 못 건넌다.
**단일 파일로는 원본 화질을 실을 수 없다.** 이것이 구조의 한계였다.

## 복원 — git 이력 15판본에서 가장 좋은 판을 캔다

`index.html` 의 모든 과거 커밋을 훑어 패널마다 가장 해상도 높고 큰 판본을 골랐다.
어려운 건 **「같은 그림인가」를 가리는 일**이다 — 재작도한 판을 옛 판본으로 되돌리면
공들인 수술이 통째로 날아간다.

- **전역 상관계수(≥0.92)는 실패했다.** 소품 몇 개만 고친 재작도는 전역 상관이 그대로 높다 —
  s09p02·s10p03·s11p04·s12p03·s16p02 **다섯 판을 옛 판으로 되돌릴 뻔했다**(상관 0.937~0.998).
- **국소 블록 최대차**로 바꿨다. 256px로 줄이고 16×16 블록으로 나눈 뒤,
  밝기·대비를 정규화하고 블록별 최대 차이를 본다. 분포가 깨끗하게 갈렸다 —
  `{0-2: 939, 2-5: 80, 5-10: 0, 10-20: 12, 20-40: 29, 40+: 295}`.
  **d 5~10 구간이 텅 비어** 문턱을 d≤8로 잡을 근거가 됐다.

결과 — **80판이 더 좋은 판본으로 올라갔다.**
해상도 `{1024: 55, 1250: 17, 1100: 18, 1150: 13, 980: 6, 1032: 1}`

## 구조 변경 — 그림을 `images/` 파일로 분리

사용자 선택: **「아니 1번으로 하자」** (단일 파일 유지 → 파일 분리로 번복)

| | 이전 (단일 파일) | **현재 (EXTERNAL)** |
|---|---|---|
| index.html | 9.7 MB | **0.58 MB** |
| 그림 | base64로 안에 | `images/*.webp` 110개 |
| 재압축 | 예산에 맞춰 깎임 | **없음 — 원본 그대로** |

`build_local.py` 에 `EXTERNAL=1` 모드를 넣었다. 예산 사다리를 건너뛰고 파일을 링크한다.

## 검증 (규칙: 「전부 제대로 되게」)

1. **바이트 동일성** — 배포된 110장을 모두 내려받아 SHA-256을 매기고 로컬 원본과
   집계 해시 대조 → **완전 일치** `0c9431e9aca2158df56dbdd074b8337c61285f0131cac5f9dce8b43d62572728`.
   재압축 0을 실측으로 증명.
2. **깨진 그림 0** — 110장 전부 `new Image()` 로 강제 적재, 실패 0.
   해상도 분포가 빌드 산출물과 정확히 일치.
3. **클린룸 복구 시험** — 빈 디렉터리에서 README 절차를 그대로 따라 재빌드한 index.html이
   배포본과 **바이트 단위로 동일**(576,003 B / `00ede3aa2b85c558`). 복구 절차는 주장이 아니라 실측이다.
4. **기능 시험** — 패널 110 · 도해 23 · 칩 21 · 함정 165행 · 자가테스트 blur(7px) 작동 ·
   「다리 전체」가 586행 전부 폄.

## 배운 것

- **화질 진단은 지각적 유사도로 하면 안 된다.** 전역 상관은 「대체로 같은 그림」에 눈이 멀어
  국소 수술을 못 본다. 판정에는 **국소 최대차**를 쓴다.
- **재해 복구가 오히려 튼튼해졌다.** 이전엔 index.html 하나에서 base64를 뽑아내야 했지만,
  이제 그림이 git에 파일로 있다 — 클론하면 끝이다.
- **10 MB 다리가 이 프로젝트의 진짜 제약이다.** 앞으로 패널이 늘어도 EXTERNAL 모드에서는
  화질을 깎을 이유가 없다. 다만 **이미지는 3묶음으로 나눠 올려야** 하고,
  **그림을 먼저 올린 뒤 index.html을 올려야** 깨진 링크 구간이 생기지 않는다.
